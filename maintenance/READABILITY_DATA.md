# Редактура баз данных, сообщений, алгоритмов и интервью

Дата: 6 октября 2026 года.

## Область

Проверены и изменены 73 Markdown-страницы: `docs/databases/**` — 29, `docs/messaging/**` — 13, `docs/algorithms/**` — 22, `docs/interviews/**` — 9. Из них 64 тематические статьи и 9 страниц навигации. Обязательный порядок изучения не добавлялся; пути файлов сохранены.

В этой редактуре менялось основное объяснение, а не добавлялся новый универсальный блок. Старые списки терминов заменены причинным рассказом: задача, наблюдаемый результат, механизм, условия применения. Сохранены содержательные SQL-сценарии конкуренции, примеры данных, схемы и код учебного Go-модуля. Вопросы и скрытые ответы вычитаны отдельно: 130 вопросов по 64 статьям. Переведены подписи схем и названия статей; машинные имена API и команды оставлены узнаваемыми.

## Конкретные изменения

- **MVCC.** Вместо «tuple / snapshot / visibility / cleanup» сначала разобрана цена 100 и новая версия 120: кто какую видит, почему старая версия нужна и когда VACUUM получает право освободить её место. Затем идут служебные поля и HOT с оговоркой про BRIN.
- **WAL.** Вместо «flush / durable log / replay от checkpoint» объяснено, почему журнал сохраняют до страницы и почему COMMIT может ответить раньше записи таблицы. Каждая команда SHOW и поле статистики имеют значение для читателя. Нижний повтор принципа PITR сокращён до дополнительного объяснения ветви истории timeline.
- **Redis Cluster.** Вместо «routing / keyspace / topology / multi-key» показаны слот, его владелец, перенос и разница MOVED/ASK. В вопросах больше нет смеси «горячий key / shards / local cache / batching».
- **Kafka.** Отправитель, получатель, часть потока, подтверждение и позиция введены через конкретное действие. ISR, LSO и транзакционная граница объяснены до уточнений. Таблица обработки 10/11/12 показывает, почему нельзя перескочить незавершённую запись. Порядок эффект → позиция разобран отдельно от гарантии самого брокера.
- **Алгоритмы.** Удалены повторяющиеся короткие разделы с английскими «pattern / predicate / invariant / complexity». Каждая тема объясняет движение границ или состояние и сохраняет конкретную трассу. Все десять Go-примеров получили индивидуальное объяснение входа, результата, механизма и ограничений; программные блоки не изменены.
- **Интервью.** Вместо перечня «ownership / mitigation / impact» объяснена причинная история инцидента. Секции программирования, платформы и проектирования говорят, какое действие демонстрирует навык. Исторические публичные описания Avito отделены от конкретной вакансии. Переписаны навигационные страницы и тематический указатель.

## Технические уточнения

Редактура не обновляла версии продуктов: сохранены ранее проверенные PostgreSQL 18.6, Redis Open Source 8.10.2, Kafka 4.3.1 и Go 1.27.1.

Уточнено, что ISR включает ведущую копию, а не только догоняющих. Добавлено объяснение ELR Kafka 4.x: некоторые копии вне текущего ISR могут оставаться безопасными кандидатами ведущего; это отличается от произвольного unclean election. На новых кластерах с 4.1 механизм включён по умолчанию. Сверено с [документацией Kafka 4.3 ELR](https://kafka.apache.org/43/operations/eligible-leader-replicas/).

Значения команд и полей `pg_stat_activity` / `pg_stat_wal` сверены с [PostgreSQL 18: статистика](https://www.postgresql.org/docs/18/monitoring-stats.html), принцип порядка журнала — с [PostgreSQL 18: WAL](https://www.postgresql.org/docs/18/wal-intro.html). Сохранены развёрнутые SQL-сценарии конкуренции и безопасный разбор перевода; библиотечные API и поведение Go-функций не менялись. Сравнение fenced SQL с HEAD показало не только перевод комментариев: при редактуре были удалены предварительные блоки, часть которых показывала уникальные операции. После проверки восстановлены отдельные примеры индексов lower/частичного набора, диагностики блокировщиков, выдачи задачи через SKIP LOCKED с изменением статуса, условного UPDATE по версии, SAVEPOINT с ожидаемой ошибкой и CREATE STATISTICS с повторным ANALYZE. В курсорном примере восстановлен подходящий составной индекс; в inbox явно выделена транзакция обработки, а outbox дополнен условным изменением заказа и вставкой события в одном BEGIN/COMMIT. Для каждого даны схема, результат и условия. Остальные удалённые краткие фрагменты повторяют сохранённые полные примеры; побайтовая идентичность SQL не заявляется. Новые SQL-примеры сверены со спецификацией PostgreSQL 18, но не запускались против живого сервера.

## Выполненные проверки

- `go test -v ./...` в `docs/algorithms/examples` с Go 1.27.1: все 17 тестов успешны. Проверяется существующий модуль, его функции и тесты не редактировались.
- Программные блоки `go-examples.md` сравнены с HEAD: десять блоков идентичны. Изменены только названия разделов и объяснения.
- Инвентаризация: 64 статьи имеют раздел самопроверки; всего 130 вопросов. Девять навигационных страниц объясняют выбор темы вместо обязательного маршрута.

SQL и команды Redis/Kafka не запускались против живого окружения. Счётчики, задержки и формы планов остаются учебными там, где это указано. Структурная проверка и тесты не являются доказательством понимания читателем; рендер всех схем и интеграционную проверку GitBook выполняет основной агент. Финальный текст ещё можно оценивать по новым вопросам конкретного читателя, без обещания «одного чтения достаточно всем».
