# Согласованность: какие значения увидит читатель

Модель согласованности описывает, как чтения связаны с записями. Фраза «данные когда-нибудь обновятся» недостаточна для понимания поведения клиента.

## Как это работает

При линейризуемости завершённая запись видна последующим операциям так, будто существует одна актуальная копия. При причинной согласованности читатель не должен увидеть ответ раньше сообщения, на которое отвечали. При eventual consistency копии сходятся после прекращения изменений и восстановления доставки, но чтение пока может быть старым.

Отдельные гарантии относятся к одной сессии: чтение своей записи позволяет после редактирования сразу увидеть своё изменение; монотонные чтения не возвращают клиента назад на более старую версию. Такие гарантии могут быть реализованы передачей номера версии или обращением к владельцу записи.

Модель согласованности копий не равна уровню изоляции SQL-транзакций. Сначала опишите правило продукта и наблюдаемое поведение, затем выберите механизм. Для поиска допустима задержка; для запрета повторного списания нужна более строгая граница.

## Разобранный пример

Изначально x=0. A записал x=1 и получил успех. После этого B начал чтение и получил 0. Линейризуемость одного ключа нарушена; чтение отстающей копии с eventual consistency может допускать такой ответ. Если старый результат получил сам A, нарушена и гарантия чтения своей записи.

Последовательная согласованность допускает общий порядок, не обязанный совпадать с реальным временем. Сериализуемость SQL относится к целым транзакциям и не означает чтение самой свежей реплики каждым запросом. Поле version помогает только если сервер действительно проверяет требуемую версию, ждёт её или перенаправляет чтение.

## Проверь себя

1. Почему одного поля version недостаточно?
2. Чем чтение своей записи слабее общей линейризуемости?

<details>
<summary>Ответы</summary>

1. Оно не обеспечивает проверку и ожидание нужного состояния.
2. Оно ограничивает наблюдение конкретной сессии, а не всех операций всех клиентов.

</details>
