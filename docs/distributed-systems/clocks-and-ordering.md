# Часы и порядок событий

Время на двух машинах может отличаться. Поэтому timestamp события не всегда показывает, какое изменение действительно произошло раньше.

## Как это работает

Часы корректируют синхронизацией, но остаются погрешности и скачки. Для измерения длительности внутри процесса используют монотонное время, которое не должно идти назад из-за перевода часов. Для срока в распределённом протоколе учитывают погрешность и задержку передачи.

Если событие B возникло после получения A, между ними есть причинная связь. Логические часы Лампорта увеличивают счётчик при событиях и передаче сообщений: причинно более позднее событие получает больший номер. Обратное неверно: больший номер ещё не доказывает причину.

Для изменений одного объекта проще назначать последовательную версию у владельца записи. Выбор победителя только по настенным часам может потерять изменение при неверном времени. Любая схема разрешения конфликтов должна объяснять, что происходит с двумя независимыми записями.

## Разобранный пример

A отправил событие с логическим временем 5. У B счётчик 3; при получении B устанавливает max(3,5)+1=6, следующее событие получает 7. Независимый C может иметь 10, не получив ни одного сообщения B: больший номер не доказывает причинную связь.

Векторные отметки [2,0] и [1,1] несравнимы. Первая сторона видела два события A, вторая — по одному от A и B. Это независимые версии, а способ объединения зависит от данных: множества можно объединить, две новые цены нельзя просто сложить. Монотонная часть времени обычно не переносится при сериализации через сеть.

## Проверь себя

1. Что доказывает больший номер Лампорта?
2. Почему нельзя сравнивать локальные монотонные часы разных процессов?

<details>
<summary>Ответы</summary>

1. Только порядок по счётчику; причинность в обратную сторону он не доказывает.
2. У них нет общей произвольной точки отсчёта, гарантированной таким сравнением.
