# Сложность алгоритмов

Сложность описывает, как растёт работа алгоритма с размером входа. `O(n)` означает линейный рост верхней оценки: удвоение входа даёт примерно удвоение числа базовых операций, но не обещает конкретных секунд.

## Как считать

Один проход — `O(n)`. Перебор всех пар — `O(n²)`. Уменьшение области вдвое — `O(log n)`. Сортировка сравнением обычно — `O(n log n)`. Перечисление всех подмножеств уже имеет `2ⁿ` ответов, поэтому ограничение результата важнее мелкой оптимизации.

Считайте не отступы циклов, а суммарное число движений и вызовов. Если левая граница вложенного цикла только растёт, она может сделать всего n шагов за всю программу. Ниже пример, где два вложенных цикла остаются линейными.

## Память и дорогие операции

Отдельно считайте дополнительную память и память результата. Рекурсия тоже занимает память стека. Срез участка не равен копированию, а сортировка меняет исходные данные. Хеширование длинной строки стоит работы по длине строки: одно обращение к map не всегда одна одинаковая по цене операция.

**Амортизированная** оценка распределяет редкие дорогие операции по последовательности. Например, `append` обычно дёшев, но иногда копирует весь массив. **Ожидаемая** оценка зависит от предположений о распределении. **Худший случай** ограничивает наиболее дорогой допустимый вход. Не смешивайте эти гарантии с задержкой одного запроса.

## Почему вложенный цикл бывает линейным

```text
left = 0
for right = 0..n-1:
    while окно нарушает условие:
        left++
```

Если left никогда не идёт назад и не превосходит n, суммарно while выполнит не более n шагов. Вместе с n шагами right получаем O(n), хотя циклы вложены. Если left каждый раз сбрасывать в 0, получится до n² шагов.

Для n=100000 квадратичный перебор пар делает около 5 миллиардов сравнений; n log₂n — около 1.7 миллиона на уровне порядка величины. Это не оценка секунд: дорогая сериализация одного элемента может доминировать.

Амортизированная O(1) append означает среднюю стоимость **по последовательности операций**, а не вероятностную или гарантированную latency каждого append. Один рост массива копирует O(n). Ожидаемая O(1) hash lookup опирается на распределение, ключ и реализацию; хеширование длинной строки само занимает работу по длине. Для вывода всех подмножеств Ω(n·2ⁿ) памяти/копирования результата естественны даже при O(n) рабочем стеке.

## Проверь себя

1. **Два вложенных цикла всегда дают O(n²)?**

   <details>
   <summary>Ответ</summary>

   Нет. Если обе границы движутся только вперёд, суммарно они могут сделать O(n) шагов.

   </details>

2. **Чем амортизированная оценка отличается от цены худшей отдельной операции?**

   <details>
   <summary>Ответ</summary>

   Редкую дорогую работу распределяют по последовательности. Один отдельный шаг всё ещё может быть дорогим.

   </details>
