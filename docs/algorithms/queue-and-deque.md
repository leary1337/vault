# Очередь и двусторонняя очередь

Очередь выдаёт элементы в порядке добавления: первый пришёл — первый ушёл. Она нужна для BFS и распределения задач. Двусторонняя очередь, deque, позволяет добавлять и удалять с обоих концов.

## Как быстро найти максимум каждого окна

Если окно из K элементов движется вправо, можно хранить не все значения, а индексы кандидатов на максимум. Их значения идут по убыванию. Удаляйте слева вышедшие из окна индексы. Перед добавлением нового удаляйте справа меньшие: они слабее и уйдут раньше нового, значит больше не понадобятся.

Вершина слева всегда даёт максимум. Каждый индекс добавляется и удаляется не более одного раза: общий проход `O(n)`, память `O(K)`. Сравнение всех K элементов для каждого окна стоило бы `O(nK)`.

## Реализация очереди в Go

Вместо копирования всех элементов при каждом извлечении держите индекс головы или кольцевой буфер. Простое `q=q[1:]` сохраняет ссылку на исходный массив и может удерживать память. Для указателей очищайте использованные позиции при полном владении данными.

Определите смысл K=0, K больше входа и равных максимумов. Для одного значения максимума равных кандидатов можно удалять или сохранять; для первого индекса политика должна быть точной.

## Максимум окна k=3

Вход[1,3,-1,-3,5]. После первых трёх deque индексов[1,2]: value3 вытеснил1, максимум3. После -3 стек кандидатов[1,2,3], максимум3. При5 индекс1 выходит за окно, значения -3,-1 слабее нового5 и удаляются справа; deque[4], максимум5. Ответ[3,3,5].

Старший более слабый кандидат бесполезен: новый больше и выйдет из окна позже. Это доказательство каждого pop справа. Каждый индекс входит/выходит максимум один раз, O(n). Равенства можно удалять или сохранять в зависимости от нужного tie-breaker; для одного значения maximum оба варианта допустимы.

Для очереди BFS в Go индекс головы позволяет не копировать хвост при каждом извлечении. Если очередь содержит указатели, очистка обработанных позиций и периодическое уплотнение или кольцевой буфер помогают не удерживать объекты. Срез `q=q[1:]` не гарантирует освобождения исходного массива.

## Проверь себя

1. **Почему из кандидатов справа удаляют меньшие значения?**

   <details>
   <summary>Ответ</summary>

   Новое значение больше и выйдет из окна позже, поэтому прежнее уже не станет максимумом.

   </details>

2. **Почему копирование хвоста при извлечении делает очередь дорогой?**

   <details>
   <summary>Ответ</summary>

   Оно сдвигает много элементов на каждом шаге и может дать квадратичную работу.

   </details>
