# Префиксные суммы

Префиксная сумма запоминает сумму от начала массива до каждой границы. Тогда сумма любого участка получается вычитанием двух готовых значений, без повторного прохода по элементам.

## Почему нужен ноль в начале

Пусть `prefix[0]=0`, а `prefix[i+1]=prefix[i]+a[i]`. Сумма участка `[left,right)` равна `prefix[right]-prefix[left]`: из суммы до правой границы вычитается всё до левой. Построение стоит `O(n)` времени и памяти, каждый запрос суммы — `O(1)`.

Если исходный элемент изменился, многие префиксы устарели. Для частых изменений и запросов рассмотрите дерево Фенвика или отрезков: обычная готовая таблица отвечает другой модели данных.

## Как считать участки заданной суммы

Для текущей суммы S нужен предыдущий префикс `S-target`. Хеш-таблица хранит частоты предыдущих сумм. Каждое совпадение задаёт отдельное начало, поэтому нужен счётчик, а не bool. Сначала считайте совпадения, потом добавляйте текущую границу: иначе при target=0 появится пустой участок.

Количество участков может быть `n(n+1)/2`. Выбирайте тип и для суммы, и для ответа по границам задачи; `int64` тоже имеет конечный диапазон.

## Числа и границы

Для a=[2,-1,3] prefix=[0,2,1,4]. Участок [1,3) содержит -1 и3: prefix[3]-prefix[1]=4-2=2. Дополнительный нулевой элемент делает пустой префикс обычной границей.

```go
func countSum(a []int64, target int64) int64 {
	seen := map[int64]int64{0: 1}
	var sum, answer int64
	for _, value := range a {
		sum += value
		answer += seen[sum-target]
		seen[sum]++
	}
	return answer
}
```

Для `[1,-1,1]` и суммы 1 есть три участка: `[0,1)`, `[0,3)`, `[2,3)`. Таблица содержит частоты только предыдущих префиксов. Сначала поиск, затем сохранение текущего префикса не допускает пустой участок при цели 0. Суммы и число ответов должны помещаться в `int64`; тип не даёт бесконечной точности.
