# Сортировка

Сортировка задаёт порядок элементов. После неё можно сравнивать соседей, применять двоичный поиск или объединять интервалы. Она имеет цену и может изменить исходные данные, поэтому не добавляйте её автоматически.

## Как выбрать порядок

Сравнение должно быть согласованным: если A раньше B, а B раньше C, то A раньше C. Результат не должен зависеть от случайного числа или меняющегося времени. Сравнивайте поля напрямую; вычитание двух целых может переполниться и поменять знак.

Стабильная сортировка сохраняет исходный порядок элементов с одинаковым ключом. Это удобно после предыдущей сортировки, но не гарантирует одинаковый ответ для разных входных порядков. Для этого добавьте явный дополнительный ключ, например уникальный id.

## Сложность и условия

Сортировки сравнением обычно требуют `O(n log n)`. Сортировки подсчётом и по разрядам используют дополнительные ограничения ключей и память, поэтому не опровергают нижнюю границу для произвольного сравнения. Память зависит от алгоритма и реализации.

В Go `slices.SortFunc` меняет слайс. Для сохранения входа сортируйте копию. Для `NaN` и равных значений нужен определённый порядок; простой оператор `<` не задаёт всех необходимых отношений для произвольных чисел с плавающей точкой.

## Равные ключи и стабильность

Записи `[(Анна,2),(Борис,1),(Вера,2)]` при стабильной сортировке по оценке дадут Борис, Анна, Вера: равные сохраняют исходный порядок. Обычная сортировка не обещает Анну перед Верой. Если результат не должен зависеть от входного порядка, сравнивайте оценку, затем уникальный id.

```go
type PersonScore struct {
	ID    int
	Score int
}

func sortScores(a []PersonScore) {
	slices.SortFunc(a, func(x, y PersonScore) int {
		if c := cmp.Compare(x.Score, y.Score); c != 0 {
			return c
		}
		return cmp.Compare(x.ID, y.ID)
	})
}
```

Нужны импорты `cmp` и `slices`, доступные API — с Go 1.21. Код сначала сравнивает Score, при равенстве — ID. `cmp.Compare` не вычитает значения, поэтому не создаёт переполнения разности. Функция меняет входной слайс. Сравнение должно быть согласованным и независимым от времени; для `NaN` нужна определённая политика порядка.

## Проверь себя

1. **Даёт ли стабильная сортировка одинаковый порядок для любого входа?**

   <details>
   <summary>Ответ</summary>

   Нет. Она сохраняет прежний порядок равных ключей. Независимость от входа требует дополнительного ключа.

   </details>

2. **Почему сравнение через вычитание опасно?**

   <details>
   <summary>Ответ</summary>

   Разность целых может переполниться и нарушить знак и согласованность порядка.

   </details>
