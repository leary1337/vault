# Двоичный поиск

Двоичный поиск отбрасывает половину области ответов за шаг. Он работает, когда проверяемое условие меняется в одном направлении: например, сначала элементы меньше 3, затем все не меньше 3. Такое условие называют **монотонным**.

## Почему можно отбросить половину

Ищем первую позицию с `a[i]>=target` в отсортированном массиве. Если средняя позиция подходит, ответ не правее неё: переносим правую границу на середину. Если не подходит, все позиции до середины тоже меньше цели: переносим левую границу за середину.

Рабочая область `[lo,hi)` включает lo и исключает hi. Пока `lo<hi`, середина `lo+(hi-lo)/2` лежит внутри массива. Когда границы совпали, получена позиция вставки. Она может быть равна длине: нужного значения в массиве тогда нет. Для проверки наличия отдельно проверьте границу и равенство.

## Цена и условия

Для n элементов выполняется `O(log n)` проверок, дополнительная память `O(1)`. Если сначала нужна сортировка, она добавляет `O(n log n)`. Если одна проверка сама стоит `O(n)`, умножайте её цену на число шагов поиска.

Частые ошибки: смешать включённую и исключённую границу, не уменьшать область на шаге, считать позицию вставки найденным элементом, использовать немонотонное условие. Середина через `(lo+hi)/2` также может переполнить целый тип.

## Трасса lower bound

Для a=[1,3,3,7], target=3:

| lo | hi (не включён) | mid | Решение |
| --- | --- | --- | --- |
| 0 | 4 | 2 | a[2]>=3 → hi=2 |
| 0 | 2 | 1 | a[1]>=3 → hi=1 |
| 0 | 1 | 0 | a[0]<3 → lo=1 |

Ответ 1. До lo все элементы меньше target; начиная с hi все проверенные справа подходят. Возвращённая позиция может равняться len(a), поэтому для проверки наличия нужен i<len(a) && a[i]==target.

Поиск по ответу: минимальная вместимость машины для перевозки грузов в D рейсов. Predicate «вместимость C достаточна» монотонен: увеличение C не делает допустимую перевозку невозможной. Если проверка C требует O(n), итог O(n log range), не просто O(log n). Верхняя граница и сумма грузов должны помещаться в тип.
