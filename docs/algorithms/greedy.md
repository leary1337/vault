# Жадные алгоритмы

Жадный алгоритм делает лучший доступный локальный выбор и не возвращается к нему. Он прост и быстр, **если доказано**, что такой выбор не мешает получить лучший общий результат.

## Как доказать выбор

Для максимального числа непересекающихся встреч выбирают встречу с самым ранним концом. Она оставляет не меньше времени для остальных. В оптимальном решении первую встречу можно заменить выбранной без уменьшения числа следующих. Это доказательство обменом, а не наблюдение на нескольких тестах.

Далее повторяют выбор среди встреч, начинающихся после окончания выбранной. Сортировка по концу стоит `O(n log n)`, проход — `O(n)`. Нужно определить, считаются ли встречи с общей границей пересекающимися.

## Когда метод ломается

Для минимального числа монет выбор самого большого номинала не всегда оптимален: пример ниже даёт контрпример. Если доказательства нет, рассмотрите [динамическое программирование](dynamic-programming.md) или полный перебор с отсечением.

Вес встречи, обязательный элемент или отрицательная цена меняют условие задачи. Нельзя использовать прежний жадный выбор только потому, что названия похожи. На интервью объясните, какое свойство делает выбор безопасным и что перестанет работать без него.

## Встречи: выбирать ранний конец

Интервалы [1,3),[2,5),[3,4),[4,6). Сортируем по end: выбираем [1,3), выбираем [3,4), потому что start>=3, пропускаем [2,5), выбираем [4,6). Ответ3 встречи. Критерий самое раннее начало выбрал бы длинную [0,100) вместо многих коротких.

Доказательство обменом: первая встреча оптимального набора заканчивается не раньше выбранной greedy. Заменив её на самую рано заканчивающуюся, не перекрываем последующие встречи и не уменьшаем количество. Повторяем для оставшегося хвоста. Это объясняет выбор конца; аналогичное доказательство для «самой короткой встречи» не получается.

Монеты `[1,3,4]`, сумма 6: жадный выбор даёт 4+1+1 — три монеты; оптимум 3+3 — две. Здесь нужна [динамика](dynamic-programming.md) или другой доказанный метод. Несколько успешных тестов не заменяют доказательство: ищите контрпример. Вес встреч, обязательные элементы и отрицательные цены меняют исходную задачу.

## Проверь себя

1. **Почему выбор раннего конца встречи безопасен?**

   <details>
   <summary>Ответ</summary>

   Им можно заменить первую встречу оптимального решения, не оставив меньше времени для следующих.

   </details>

2. **Почему выбор самой большой монеты неверен для [1,3,4] и суммы 6?**

   <details>
   <summary>Ответ</summary>

   Получится 4+1+1 — три монеты, тогда как 3+3 — две.

   </details>
