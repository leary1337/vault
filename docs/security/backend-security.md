# Защита backend: почему одной проверки JSON мало

Корректный JSON может содержать чужой ID, адрес внутреннего сервиса или строку, которую ошибочно исполнят как команду. Проверка формата необходима, но каждой опасной операции нужны собственные границы. Сначала определите, какое действие пользователь может заставить сервер выполнить.

## CORS и CSRF

CORS управляет тем, разрешит ли браузер странице читать ответ другого сайта. Это не вход в систему и не сетевой фильтр: обычный HTTP-клиент вне браузера может его игнорировать. Разрешайте конкретные доверенные origins — сочетания схемы, имени и порта. Для запросов с автоматически приложенными данными доступа нельзя произвольно использовать wildcard origin.

CSRF возникает, когда чужая страница заставляет браузер отправить нежелательный запрос с уже имеющейся cookie. Сервер может принять его за действие пользователя. Используйте выбранную модель защиты: SameSite, специальный токен и проверку Origin/Fetch Metadata. GET не должен выполнять запрошенное изменение состояния. Внедрённый скрипт внутри доверенной страницы (XSS) может обойти часть этой защиты, поэтому требует отдельного предотвращения.

## SSRF: запрос сервера по адресу пользователя

Сервис загрузки картинки принимает URL. Если он без проверки скачает `http://127.0.0.1/...`, пользователь получает способ обращаться к внутренним ресурсам от имени сервера. Это SSRF. Ограничивайте допустимые схемы, имена, порты и **фактические адреса подключения**, включая IPv6.

Одной предварительной проверки DNS недостаточно: при реальном подключении ответ мог измениться. Перенаправление также может вести к запрещённому адресу. Проверяйте каждый переход и привязывайте разрешение к реально выбранному адресу, сохраняя корректные имя HTTP и SNI. Сетевые ограничения исходящих запросов и отдельные права процесса уменьшают последствия ошибки. Ниже разобран запрос к внутреннему metadata-сервису.

## Внедрение инструкций

Для SQL используйте параметры: значение остаётся данными, а не частью текста запроса. Имена таблиц и направление сортировки обычно нельзя подставить обычным параметром, поэтому их выбирают из разрешённого списка. Права подключения к БД ограничивают возможный ущерб.

Для запуска процесса используйте API с отдельными аргументами, а не конкатенацию shell-команды. При этом пользовательский аргумент может оказаться опасным флагом самой программы: нужен допустимый набор значений и операций. В шаблонах, заголовках и журналах применяйте кодирование и библиотеку, подходящие конкретному контексту.

## Пути и загружаемые файлы

Строка с `../` может выйти из разрешённого каталога, но удаление этих символов не решает все варианты пути и символических ссылок. По возможности пользователь получает ID, а сервер сам выбирает путь. Если путь нужен, обеспечьте работу внутри разрешённого каталога с учётом конкурентной смены ссылок; используйте подходящие directory-relative операции ОС.

Загруженный файл получает имя сервера. Исходное имя — метаданные, а не команда построения пути. Ограничьте размер, допустимый тип, распаковку архивов и права хранения. Маленький сжатый архив может развернуться в огромные данные и исчерпать ресурс.

## Защита мощности и ошибок

Ограничивайте тело, объём распаковки, размер batch/page, глубину вложенности и число одновременных дорогих операций. Ограничение частоты не заменяет права на объект. Для общего ограничителя определите, что произойдёт при его недоступности: разрешение всех запросов и отказ всем имеют разные последствия.

Наружу возвращайте понятный код ошибки без SQL, внутренних путей и стеков. Внутри сохраняйте данные для сопоставления событий без секретов. Проверяйте некорректный ввод, конкурентные случаи и освобождение ресурсов после ошибки, а не только успешный запрос.

## Разбор на примере

Функция «загрузить фото по URL» даёт пользователю возможность заставить сервер выполнить исходящий запрос. После разрешённого адреса может идти перенаправление на внутреннюю сеть; DNS между проверкой и подключением может измениться. Контролируйте каждый переход и адрес реального соединения, включая IPv6 и представления IPv4 через IPv6. Запрет одной строки `127.0.0.1` не закрывает все локальные и служебные адреса.

SQL-параметр безопасно передаёт **значение**, но не произвольное имя колонки. Для ORDER BY выбирайте колонку и направление из конечного списка. API запуска с отдельными аргументами убирает shell-разбор, но пользовательский аргумент всё ещё может быть опасным флагом выбранной утилиты.

`Access-Control-Allow-Origin: *` не проверяет личность. CORS касается чтения ответа браузером, а CSRF — нежелательного действия с автоматически приложенной cookie. Обычный curl не обязан соблюдать CORS.

При загрузке файла ограничивайте байты до полного чтения и выделения памяти. Content-Type пользователя не доказывает реальный формат. Для архива отдельно проверяйте выход за каталог и размер после распаковки: маленькое сжатое тело может занять огромное место.
