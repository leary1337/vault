# Утечка горутин: кто ждёт того, кто уже ушёл

Горутина считается утёкшей, когда её работа больше не нужна, но она не может закончиться. Она продолжает занимать память и удерживать связанные объекты.

## Как это работает

Типичный случай: клиент отменил запрос, получатель ушёл, а отправитель навсегда ждёт передачи в канал. Сборщик мусора не останавливает такую горутину: её стек остаётся живым.

Сравните число горутин после одинаковых циклов нагрузки и восстановления. Снимок goroutine-профиля показывает их стеки: много одинаковых ожиданий указывает место остановки. Сам рост при всплеске нормален, если после завершения работы число возвращается.

Ожидание чтения, отправки и блокировки должно иметь предусмотренный путь выхода. Отмена контекста работает только там, где код её проверяет. Владелец этапа обработки закрывает выход после завершения всех отправителей; принимающая сторона не закрывает канал, пока в него могут писать.

## Разобранный пример

После каждой тысячи отменённых запросов остаётся ещё тысяча горутин со стеком mapStage → отправка в канал. CPU низкий: они ждут получателя, который уже ушёл. Отправку оборачивают в select с веткой ctx.Done(). Чтение входа тоже требует отменяемого ожидания: пустой незакрытый вход иначе оставит этап навсегда.

Тест отдельно проверяет пустой вход и заблокированный выход, затем ждёт завершения с конечным сроком. Неиспользуемые таймеры современного Go могут собираться сборщиком мусора, но горутина, бесконечно читающая ticker.C, сама не завершится. Ticker.Stop не закрывает канал; нужен сигнал выхода.

## Отправка, которую можно прекратить

Это фрагмент внутри функции без возвращаемого значения. `out` — канал результата, `value` — готовое значение, `ctx` — контекст работы. Получатель мог уже уйти после отмены:

```go
select {
case out <- value:
case <-ctx.Done():
    return
}
```

Первая ветка передаёт значение, если получатель готов или в буфере есть место. Вторая выходит, когда контекст отменён, даже если передать значение некому. Если обе готовы, выбирается одна: отмена не имеет автоматического приоритета.

Так закрыт путь зависания при отправке, но другие ожидания требуют такой же проверки. Чтение пустого незакрытого входа, сетевой вызов без срока или ожидание блокировки могут оставить горутину живой. Тест проверяет отмену отдельно на заблокированном входе и выходе, затем ждёт завершения до конечного срока. Закрывать `out` вправе только владелец, знающий, что все отправители остановились.

2. Достаточно ли отменить отправку?
