# Диагностика работающего сервиса

Диагностика начинается с наблюдаемого ущерба и проверяемой гипотезы. Список инструментов полезен только после понимания, какое измерение отличит возможные причины.

## Как это работает

Сначала уточните операцию, время, версию и масштаб. Затем запишите две конкурирующие гипотезы и ожидаемые сигналы. Например, медленный SQL увеличит длительность выполнения запроса; удержание соединений увеличит ожидание пула даже при быстром SQL.

Выберите инструмент под вопрос. Метрики показывают масштаб и динамику; трассировка — путь одного запроса; CPU-профиль — места вычисления; профиль горутин — ожидания. Запускайте ограниченный сбор на нужном экземпляре, сохраняя факты до перезапуска, если это не мешает восстановлению.

Изменение оценивают по пользовательскому результату при сопоставимой нагрузке. Совпадение по времени усиливает гипотезу, но окончательное объяснение требует механизма и воспроизведения. Не выполняйте одновременно несколько несвязанных действий без необходимости.

## Разобранный пример

После обновления p99 вырос с 150 до 800 мс только у новой версии. Поток прежний, ожидание пула 600 мс, SQL 30. Гипотеза A: код удерживает соединение во время внешнего вызова. Гипотеза B: SQL стал дорогим. Прежнее время SQL плохо поддерживает B.

В медленной трассировке сравните интервал транзакции и внешний вызов со старой версией. Ограниченный откат помогает проверить связь: после него при том же потоке должны снизиться ожидание и время ответа. Затем воспроизведите удержание в тесте, чтобы причина не осталась одной корреляцией.

```mermaid
flowchart LR
    Impact[Пользовательский симптом] --> Scope[Какая версия и область]
    Scope --> Hyp[Гипотеза и ожидаемый сигнал]
    Hyp --> Evidence[Trace, профиль, ресурс]
    Evidence --> Mit[Ограниченное исправление]
    Mit --> Verify[SLI восстановлен]
```

## Проверь себя

1. Как выбрать между профилем CPU и трассировкой?
2. Почему исчезновение симптома после перезапуска не объясняет причину?

<details>
<summary>Ответы</summary>

1. Профиль отвечает о вычислениях; трассировка помогает разделить длительности и ожидания запроса.
2. Перезапуск сбрасывает состояние, но механизм накопления может повториться.

</details>
