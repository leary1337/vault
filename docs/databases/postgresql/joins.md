# Соединение таблиц: JOIN

`JOIN` соединяет строки по условию. Если у клиента три заказа, соединение клиента с заказами вернёт три пары. Это ожидаемый результат: сначала определите, сколько строк должен представлять ответ.

## Какие строки сохраняются

`INNER JOIN` оставляет совпавшие пары. `LEFT JOIN` сохраняет и клиентов без заказов, заполняя поля заказа `NULL`. `RIGHT` и `FULL` сохраняют правую или обе стороны. `CROSS JOIN` строит все пары. Если нужно лишь узнать, есть ли заказ, используйте `EXISTS`: он не размножает клиента по числу заказов.

Условие в `ON` определяет совпадение. `WHERE` фильтрует уже полученный результат. Поэтому `WHERE order.status='paid'` после `LEFT JOIN` удалит клиента без заказа: его `NULL` не равен `'paid'`. Если клиент должен остаться, фильтр заказов обычно относится к `ON`.

Сравнение с `NULL` даёт неизвестное значение. Для отсутствия используйте `IS NULL`. `IS NOT DISTINCT FROM` позволяет специально считать два `NULL` равными. `NOT IN` с `NULL` внутри подзапроса способен не вернуть ожидаемые строки; часто понятнее `NOT EXISTS`.

## Как выполняется соединение

При **Nested Loop** для каждой строки слева ищутся строки справа. Это выгодно для небольшой левой стороны и быстрого поиска по индексу; без них число проверок может вырасти квадратично.

При **Hash Join** сервер строит хеш-таблицу одной стороны и ищет совпадения другой по равенству. При нехватке памяти часть работы уходит на диск. **Merge Join** идёт по двум отсортированным наборам; сортировку дают индексы или отдельные операции.

Это способы выполнения, а не разные результаты SQL. Неполный составной ключ соединяет чужие строки, а `DISTINCT` может лишь скрыть ошибку. `LATERAL` нужен, когда правый подзапрос использует значения конкретной строки слева.

## LEFT JOIN и NULL

```sql
CREATE TABLE join_customers(id integer PRIMARY KEY);
CREATE TABLE join_orders(id integer PRIMARY KEY,customer_id integer,status text);
INSERT INTO join_customers VALUES (1),(2);
INSERT INTO join_orders VALUES (10,1,'paid'),(11,1,'new');
SELECT c.id AS customer,o.id AS paid_order
FROM join_customers c LEFT JOIN join_orders o
ON o.customer_id=c.id AND o.status='paid' ORDER BY c.id;
-- (1,10), (2,NULL)
```

Перенесите `status='paid'` в `WHERE`: строка `(2,NULL)` исчезнет. Сравнение отсутствующего значения с `'paid'` даёт неизвестное значение, а `WHERE` оставляет только true. Если нужно лишь наличие оплаченного заказа, `EXISTS` оставляет клиента один раз независимо от числа таких заказов.

```sql
SELECT 2 NOT IN (SELECT customer_id FROM join_orders
                 UNION ALL SELECT NULL::integer);
-- NULL (unknown), не true
```

`NOT EXISTS` проверяет отсутствие совпадающей строки и не имеет ловушки `NOT IN` с `NULL`. При двух независимых связях «один ко многим», например заказах и телефонах клиента, соединение может перемножить их и завысить `SUM`. Сначала агрегируйте каждый набор до одной строки клиента или явно определите нужную кратность.

Для Merge Join и Hash Join серверу нужно поддерживаемое сравнение по равенству. Дополнительное условие диапазона может проверяться отдельно как фильтр. Его наличие не означает, что любой произвольный диапазон можно эффективно соединить тем же алгоритмом.
