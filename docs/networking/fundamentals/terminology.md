# Термины компьютерных сетей

Термины помогают указать точную границу проблемы. Сначала различайте обещанный результат, способ его вызова и правила обмена.


| Термин | Простое объяснение | Пример |
|---|---|---|
| Сервис уровня | Что уровень предоставляет верхнему | TCP предоставляет поток байтов |
| Интерфейс | Как верхний уровень использует сервис | read/write сокета |
| Протокол | Как участники договариваются по сети | начальный обмен TCP и номера байтов |
| Host | Конечная система с сетевым стеком | Сервер приложения |
| Link | Участок непосредственной передачи | Ethernet-сегмент |
| Route | Правило выбора ближайшего узла и интерфейса | маршрут по умолчанию через шлюз |
| Frame | Канальная оболочка текущего участка | Ethernet-кадр |
| Packet/datagram | Единица переноса IP или UDP по контексту | IP-пакет, UDP-дейтаграмма |
| Stream | Поток без прикладных границ сообщений | поток байтов TCP |

## Инкапсуляция

Сообщение верхнего уровня становится содержимым нижнего. Не у всех форматов есть завершающая часть, не всякий заголовок открыт для чтения, а запись TLS и TCP-сегмент не совпадают с вызовами Write. Указывайте, о каком уровне идёт речь.

```mermaid
flowchart LR
 A[Приложение: сообщение] --> T[Транспорт: поток или дейтаграмма]
 T --> I[IP-пакет]
 I --> F[Кадр локального участка]
```

## Пример, который отличает слова

У сервиса выросло время ответа, в которое укладываются 99% запросов (p99), а время сетевого обмена туда-обратно (RTT) осталось прежним. HTTP-запрос дополнительно ждёт очереди, вычисления и зависимые сервисы. Поэтому «сеть стала медленной» пока только гипотеза. Throughput обозначает количество завершённой работы за время; bandwidth — ёмкость канала. Увеличение ёмкости не обязательно сокращает время прохождения сигнала.

Deadline — момент, после которого вызывающая сторона прекращает ждать. Превышение срока не доказывает отмену удалённой операции. Retry — новая попытка; идемпотентность означает, что повтор имеет тот же предполагаемый эффект, что и одно выполнение.

## Проверь себя

1. Чем протокол TCP отличается от интерфейса сокетов?
2. Почему низкий RTT не доказывает быстрый ответ HTTP-сервиса?

<details>
<summary>Ответы</summary>

1. Протокол определяет сетевой обмен между сторонами, API сокетов — использование сервиса программой.
2. HTTP-время включает очереди и вычисления, которые RTT не измеряет.

</details>
