# Термины компьютерных сетей

Термины помогают указать точную границу проблемы. Сначала различайте обещанный результат, способ его вызова и правила обмена.

## Термины в этой статье

- **latency** — время ожидания результата конкретной операции.
- **RTT** — время прохождения запроса и ответа по сети.
- **endpoint** — конкретный адрес службы или сторона соединения.

| Термин | Простое объяснение | Пример |
|---|---|---|
| Сервис уровня | Что уровень предоставляет верхнему | TCP предоставляет поток байтов |
| Интерфейс | Как верхний уровень использует сервис | read/write сокета |
| Протокол | Как участники договариваются по сети | TCP SYN, ACK, sequence numbers |
| Host | Конечная система с сетевым стеком | Сервер приложения |
| Link | Участок непосредственной передачи | Ethernet-сегмент |
| Route | Правило выбора next hop/interface | default route через шлюз |
| Frame | Канальная оболочка текущего участка | Ethernet-кадр |
| Packet/datagram | Единица переноса IP или UDP по контексту | IPv6 packet, UDP datagram |
| Stream | Поток без прикладных границ сообщений | TCP byte stream |

## Инкапсуляция

Сообщение верхнего уровня становится содержимым нижнего. Не у всех форматов есть footer, не всякий header открыт для чтения, а TLS record и TCP segment не совпадают с вызовами Write. Указывайте, о каком уровне идёт речь.

```mermaid
flowchart LR
 A[Приложение: сообщение] --> T[Транспорт: поток или дейтаграмма]
 T --> I[IP-пакет]
 I --> F[Кадр локального участка]
```

## Пример, который отличает слова

У сервиса latency p99 выросла, но TCP RTT не изменился. RTT измеряет обратный путь транспортного обмена, а latency endpoint включает очереди, обработку и downstream. Значит «сеть медленная» пока гипотеза, а не вывод. Throughput — количество завершённой работы за время; bandwidth — потенциальная ёмкость канала. Увеличение bandwidth не обязательно уменьшает RTT.

Deadline — момент, после которого caller прекращает ждать. Timeout не доказывает, что удалённая операция отменена. Retry — новая попытка; idempotency определяет, как повтор влияет на наблюдаемый результат.

## Проверь себя

1. Чем протокол TCP отличается от интерфейса сокетов?
2. Почему низкий RTT не доказывает низкую latency HTTP endpoint?

<details>
<summary>Ответы</summary>

1. Протокол определяет сетевой обмен между сторонами, API сокетов — использование сервиса программой.
2. HTTP-время включает очереди и вычисления, которые RTT не измеряет.
