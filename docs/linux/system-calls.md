# Системные вызовы

Системный вызов передаёт ядру работу, которую приложение не может выполнить самостоятельно: открыть файл, работать с сетью, создать отображение памяти или процесс. Обычная библиотечная функция может обойтись без такого вызова или сделать сразу несколько.

## Как выполняется операция

Процессор переходит в режим ядра, которое проверяет аргументы и права. Если ресурс не готов, задача может заснуть, а планировщик запустит другую. Неблокирующий дескриптор вместо сна вернёт `EAGAIN` или `EWOULDBLOCK`; механизм готовности поможет выбрать время следующей попытки.

Частичное чтение или запись — нормальный результат: приложение обрабатывает фактический объём и при необходимости продолжает. `EINTR` означает прерывание сигналом; решение повторить зависит от операции, уже выполненной части и библиотеки. Ошибки в C обычно передаются через соглашение `errno`.

## strace

```bash
strace -f -tt -T -p "$PID"
strace -f -c -p "$PID"
strace -e trace=network,file -p "$PID"
```

`-f` следует за потоками и потомками, `-T` показывает длительность вызова, `-c` собирает сводку. Подключение меняет временное поведение и может раскрыть пути или данные. Ограничивайте процесс и время наблюдения. Для Go сопоставляйте с профилями и трассой выполнения.

## Интерпретация вывода

```text
read(7, ..., 4096) = 512
read(7, ..., 4096) = -1 EAGAIN
epoll_wait(4, ..., 128, -1) = 1
```

Это пример нормального неблокирующего чтения: 512 байт прочитаны, хотя буфер на 4096, затем данные закончились и процесс ждёт. Если протокол требует фиксированное сообщение, нужно собрать остаток.

Долгий `epoll_wait` без запросов означает полезное ожидание работы, а не обязательно медленный сервер. `futex` может быть ожиданием блокировки или нормальным механизмом сна. Причина `read` зависит от FD: файл, сокет или канал. Сопоставляйте его с `/proc/$PID/fd`, стеком и нагрузкой. Сводные проценты вызовов не объясняют бизнес-причину их количества.
