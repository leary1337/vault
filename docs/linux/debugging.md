# Диагностика Linux

Начните с конкретного симптома: какие запросы замедлились, когда и где. Определите масштаб — процесс, контейнер, узел или вся система — и недавние изменения. Затем выбирайте команду, которая проверяет гипотезу, а не случайный набор инструментов.

## 1. Процесс и очередь работы

```bash
ps -eo pid,ppid,stat,etimes,%cpu,%mem,rss,comm --sort=-%cpu
top -H -p "$PID"          # htop — интерактивная альтернатива
vmstat 1
cat /proc/pressure/{cpu,memory,io}
```

Посмотрите CPU, число готовых задач и задач в непрерываемом ожидании, переключения и подкачку. Уточните принадлежность процесса к cgroup. Низкий CPU машины не исключает лимит контейнера.

## 2. Память и ядро

```bash
free -h
cat /proc/$PID/smaps_rollup
dmesg -T | tail -200
```

Ищите признаки OOM, трудного освобождения памяти, обращения к отсутствующим страницам и ошибок устройства. `dmesg` может требовать прав и показывать чувствительные адреса.

## 3. Диск и ввод-вывод

```bash
iostat -xz 1
pidstat -d -p "$PID" 1
lsof -p "$PID"
```

Сопоставьте скорость передачи, задержку и очередь устройства с файлами процесса. `%util` зависит от устройства и параллелизма: один процент не заменяет задержку `await` и время нехватки ресурса PSI.

## 4. Сеть и дескрипторы

```bash
ss -s
ss -lntp
ss -tanp
lsof -nP -p "$PID"
```

Проверьте слушающие адреса, состояния соединений, повторные передачи, пределы FD и временных исходящих портов. Измеряйте из того же сетевого окружения, где работает приложение.

## 5. Системные вызовы и профили

```bash
strace -f -tt -T -p "$PID"
perf top -p "$PID"
perf record -F 99 -g -p "$PID" -- sleep 30
```

Применяйте после дешёвых первичных замеров и на коротком интервале: подключение и выборка добавляют нагрузку. Для Go нужны также `pprof` и трасса выполнения.

## Короткий разбор

После обновления выросла p99, число запросов в секунду прежнее, CPU и RSS стабильны. `ss` показывает много новых исходящих соединений. Гипотеза: для каждого запроса создаётся отдельный HTTP Transport, и соединения больше не используются повторно. Проверьте частоту создания соединений и `httptrace`; исправление сравните на той же нагрузке.

Если вместо этого задачи находятся в `D`, а `iostat` показывает большой `await`, изучайте хранилище и `wchan`: CPU-профиль не объясняет ожидание диска.

## Завершение

До перезапуска сохраните время, версии, значимые логи, метрики и профили. Временное облегчение отделяйте от причины. Не меняйте одновременно масштаб, настройки ядра и программу: иначе трудно установить, что помогло. Исправление проверяйте тем же сигналом при сопоставимой нагрузке; предотвращение может потребовать теста, лимита или изменения механизма.

Команды рассчитаны на Linux. Утилиты могут отсутствовать или требовать прав; на Windows эти примеры не выполнялись.
