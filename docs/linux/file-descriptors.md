# Файловые дескрипторы

**Файловый дескриптор** (FD) — небольшой номер в таблице процесса, через который он обращается к ресурсу ядра. За номером может быть файл, сокет, канал передачи данных, epoll или другой объект. Владелец должен закрыть его по всем путям завершения.

## Номер и открытый объект

`open` создаёт описание открытого файла с позицией чтения и флагами. `dup` создаёт другой дескриптор к тому же описанию, поэтому позиции общие. После `fork` унаследованные дескрипторы тоже могут разделять это описание. Флаг `FD_CLOEXEC` принадлежит самому дескриптору.

Если первый дескриптор прочитал байты, позиция второго после `dup` сдвинулась. Отдельный `open` обычно получает собственную позицию. После `close` тот же номер может быстро достаться новому объекту: старый FD не является устойчивым идентификатором.

Внутренние ресурсы создавайте атомарно с запретом наследования при запуске другой программы: `O_CLOEXEC`, `SOCK_CLOEXEC`, `accept4`. Установка флага позже может соревноваться с параллельным `fork+exec` и случайно передать сокет или секрет.

## Лимиты и диагностика

`RLIMIT_NOFILE` ограничивает дескрипторы процесса; системный предел существует отдельно. `EMFILE` обычно означает исчерпание лимита процесса, `ENFILE` — системного. Тогда могут перестать работать даже запись лога и проверка здоровья.

```bash
ls -l /proc/$PID/fd
lsof -p "$PID"
cat /proc/$PID/limits
cat /proc/sys/fs/file-nr
```

Разделите растущее число FD по типам. Много сокетов может означать нормальный пул или утечку. Сравнивайте с нагрузкой и состояниями соединений: простое повышение лимита только отложит проблему, если число продолжает расти.

## Почему удалённый файл занимает диск

```bash
find /proc/"$PID"/fd -maxdepth 1 -type l | wc -l
lsof -p "$PID" +L1
```

Первая команда считает дескрипторы процесса, вторая ищет открытые удалённые файлы. Удаление имени лога не освобождает данные, пока процесс держит FD: место освободится после закрытия последней ссылки. Поэтому `lsof +L1` полезен, когда файлы удалены, а диск всё ещё заполнен.

## Проверь себя

1. Почему удаление большого лога может не освободить место?
2. Чем `dup` отличается от повторного `open`?

<details>
<summary>Ответы</summary>

1. Открытый дескриптор сохраняет данные файла до закрытия.
2. `dup` разделяет описание и позицию; новый `open` обычно создаёт отдельную позицию.
