# Память Linux и файловый кеш

Linux использует свободную RAM для хранения недавно прочитанных файловых страниц. Это **page cache**, который ускоряет повторное чтение. Поэтому мало полностью свободной памяти не означает нехватку: часть кеша можно освободить при необходимости.

## Что занимает память

Память приложения без файлового источника — например, куча и стеки — называется анонимной. Для освобождения таких живых страниц может понадобиться подкачка на диск; если ресурсов нет, возможен OOM. Неизменённые файловые страницы можно отбросить и позже перечитать. Изменённые сначала нужно записать на диск.

Кроме приложения и кеша, есть служебные структуры ядра, общая память, tmpfs и буферы сокетов. RSS процесса считает страницы его отображений в RAM; общие страницы могут попасть в RSS нескольких процессов. PSS распределяет их стоимость между владельцами. Go-куча не покрывает весь RSS.

## Нехватка памяти и OOM

До убийства процесса система может долго искать освобождаемые страницы, писать их на диск или использовать подкачку. Эти ожидания повышают задержку. OOM killer выбирает процесс для завершения с учётом ограничений; `memory.max` cgroup может вызвать OOM внутри отдельной группы.

```bash
free -h
vmstat 1
cat /proc/meminfo
cat /proc/pressure/memory
cat /proc/$PID/smaps_rollup
dmesg -T | grep -i -E 'oom|killed process'
```

`free -h` показывает доступную память, `vmstat` — активность во времени, `/proc/meminfo` — состав. PSI памяти показывает задержки из-за нехватки ресурса. `smaps_rollup` разделяет память процесса, а журнал ядра может подтвердить OOM. Для доступа могут требоваться права.

## Отличить кеш от утечки

```text
MemFree:        500000 kB
MemAvailable: 8000000 kB
Cached:       7000000 kB
```

Это иллюстративный вывод: свободно примерно 0,5 ГБ, но оценка доступной памяти — около 8 ГБ. Большая часть файлового кеша пригодна для освобождения. Другая ситуация — растущая анонимная память, подкачка и задержки при уменьшении доступного объёма.

У двух процессов с RSS по 1 ГиБ часть страниц может быть общей: уникальный расход не обязательно 2 ГиБ. Контейнерный `memory.current` также включает категории кеша и ядра; изучайте `memory.stat`, а не только Go-профиль.

Не очищайте файловый кеш как обычное лечение: повторные чтения станут дороже, а причина останется. `oom_kill` подтверждает убийство из-за памяти; код выхода 137 означает `SIGKILL` и может быть следствием принудительной остановки по таймауту.
