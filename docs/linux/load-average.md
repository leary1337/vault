# Средняя нагрузка: load average

Linux load average — сглаженное число задач, которые выполняются, готовы выполнять работу (`R`) или находятся в непрерываемом ожидании (`D`). Это число задач, а не процент занятости CPU. Три значения описывают тенденцию примерно за 1, 5 и 15 минут; это не простое среднее строго последней минуты.

```bash
cat /proc/loadavg
uptime
ps -eo state,pid,tid,comm,wchan:32 | awk '$1 ~ /^[RD]/'
```

Команды показывают значения и задачи `R`/`D`. В таблице `ps` поле `wchan` помогает узнать, где задача ждёт в ядре.

## Одинаковое число, разные причины

```text
load average: 8.00, 6.00, 3.00
```

Восемь готовых задач на восьми доступных CPU могут просто занимать мощность. На одном CPU они создают очередь. Но восемь задач `D`, ждущих сетевую файловую систему NFS, поднимут load даже при почти свободном CPU. Поэтому нужны состояния задач, загрузка отдельных CPU, задержки диска и PSI — время ожидания ресурса.

Поле вроде `4/350` в `/proc/loadavg` отдельно показывает текущие готовые задачи и общее число задач. Оно не равно первой сглаженной цифре.

## Контейнеры

Показатель машины может включать процессы других cgroup, а конкретному контейнеру разрешены лишь определённые ядра или квота. Делить общий load на CPU limit контейнера некорректно как точный расчёт. Проверяйте его `cpu.stat`, паузы по квоте и PSI cgroup.

## Диагностический порядок

Сначала подтвердите изменение пользовательской задержки или скорости обработки. Затем проверьте занятость CPU, очередь и квоту. Найдите задачи `R` и `D`. Для `D` изучите `wchan`, `iostat`, локальное или сетевое хранилище и журнал ядра. Сопоставьте время с обновлением и нагрузкой. Для оповещений пользовательская задержка обычно полезнее одного load.
