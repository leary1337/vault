# Сигналы

**Сигнал** — асинхронное уведомление процесса или потока о событии. `SIGTERM` предлагает завершиться и допускает обработку. `SIGKILL` принудительно прекращает процесс: выполнить сохранение и уборку он уже не сможет.

## Доставка

Для сигнала выбирают действие по умолчанию, игнорирование или обработчик. Маска временно блокирует доставку. Несколько одинаковых стандартных сигналов могут объединиться в одно ожидающее уведомление; сигналы реального времени ставятся в очередь.

`SIGINT` обычно приходит от терминала, `SIGHUP` часто используют для перечитывания настроек. `SIGKILL` и `SIGSTOP` нельзя перехватить, заблокировать или игнорировать. Сигнал всему процессу может получить один подходящий поток, направленный потоку — конкретная задача.

## Корректное завершение

После `SIGTERM` приложение перестаёт принимать работу и снимает готовность принимать запросы. Затем оно закрывает слушающие сокеты, даёт завершиться активным запросам или заданиям в пределах срока, сохраняет критичное состояние и освобождает ресурсы. Если срок остановки истёк, управляющая система может отправить `SIGKILL`.

Сырой обработчик POSIX C допускает только специальные безопасные функции. Не помещайте туда произвольную сложную логику; API среды выполнения передаёт событие в безопасное для языка место.

## Команды

```bash
kill -TERM "$PID"
kill -KILL "$PID"   # только когда graceful path исчерпан
cat /proc/$PID/status | grep -E 'Sig(Pnd|Blk|Ign|Cgt)'
```

PID 1 внутри контейнера имеет особые обязанности по обработке сигналов и результатов потомков.

## Go получает сигнал через безопасный API

Фрагмент функции; нужны `context`, `os`, `os/signal`, `syscall`. Пример `SIGTERM` рассчитан на Linux:

```go
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()
<-ctx.Done()
// Здесь запускается bounded shutdown с новым context.
stop() // вернуть обычную обработку последующих сигналов
```

`stop` освобождает подписку и восстанавливает обработку, если других подписчиков нет. Отменённый `ctx` не подходит для нового ожидания завершения активных запросов: создайте отдельный контекст с ограниченным сроком.

Поскольку стандартные сигналы могут объединяться, их нельзя использовать как точный счётчик поступивших заданий.
