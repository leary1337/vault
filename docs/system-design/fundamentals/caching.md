# Кэширование: какую копию и насколько долго можно читать

Кэш ускоряет повторное чтение, сохраняя копию результата. Главный вопрос проекта — когда эта копия становится слишком старой для операции.

## Как это работает

Назовите достоверный источник, содержимое ключа, срок жизни и правило изменения. Ключ должен различать параметры и доступ: общая копия ответа не должна показывать закрытые поля другому пользователю.

Оцените нагрузку без кэша. Большая доля попаданий может скрывать зависимость БД от его доступности. Ограничьте одновременные загрузки и объедините одинаковые; допустимый старый ответ согласуйте заранее. Для изменения прав нельзя автоматически использовать тот же срок, что для публичного описания. Подробнее: [cache-aside и гонка обновления](../../backend-patterns/cache-aside.md).

## Разобранный пример

При 20 тысячах чтений/с и 95% попаданий БД получает тысячу/с. Потеря кэша увеличивает поток до двадцати тысяч. Покажите, как ограничиваются загрузки и какие запросы получат отказ.

Ключ карточки учитывает арендатора и версию формата. Если доступ зависит от пользователя, одного ad:42 недостаточно. Публичное содержимое можно кэшировать отдельно от проверки прав; личные поля нельзя выдавать из общего кэша всем.
