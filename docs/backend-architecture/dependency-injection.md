# Передача зависимостей: dependency injection

Если сервису нужен доступ к БД и текущее время, передайте их явно при создании. Тогда читатель видит зависимости, а тест может дать управляемые часы и тестовое хранилище.

## Как это работает

Альтернатива — сервис сам читает глобальную переменную БД или создаёт клиент внутри операции. Это скрывает стоимость, конфигурацию и того, кто отвечает за закрытие ресурса. Явный конструктор получает нужные зависимости и сохраняет их в полях.

Интерфейс описывает действия, необходимые потребителю. Его не обязательно создавать для каждой функции: полезнее небольшие интерфейсы на границах ввода-вывода, где действительно меняется реализация. Код сборки приложения создаёт общий пул, клиентов и сервисы, а при остановке закрывает их в согласованном порядке.

Общий пул живёт столько же, сколько приложение. Контекст отдельного запроса живёт только до его завершения, поэтому его не сохраняют в общем сервисе. DI-контейнер не обязателен: в Go обычные вызовы конструкторов часто показывают эту сборку наиболее ясно.

Ниже фрагмент конструктора: Clock и AdRepository — зависимости сервиса; time импортируется из стандартной библиотеки, а контракт AdRepository определяется приложением.

```go
type Clock interface { Now() time.Time }

type Service struct {
    repo  AdRepository
    clock Clock
}

func NewService(repo AdRepository, clock Clock) *Service {
    return &Service{repo: repo, clock: clock}
}
```

## Разобранный пример

Общий пул создаёт код запуска приложения. Сервис, получивший этот пул, не закрывает его после одного запроса: ресурс нужен другим операциям. Создатель ресурса определяет, кто им владеет и когда завершает.

В Go интерфейс хранит динамический тип и значение. При var p *SQLRepo = nil; var r AdRepository = p проверка r != nil истинна: тип присутствует, хотя указатель пустой. Поэтому проверка repo == nil не ловит все ошибки сборки. Не возвращайте типизированные пустые указатели из фабрик и проверяйте зависимости при запуске.

Тестовые часы позволяют проверить истечение срока без настоящего ожидания. Но отмена сетевой работы всё равно зависит от переданного контекста.

## Проверь себя

1. Кто закрывает общий пул?
2. Почему интерфейс с nil-указателем может быть ненулевым?

<details>
<summary>Ответы</summary>

1. Владелец жизненного цикла приложения.
2. В нём сохранён динамический тип указателя, а не только значение nil.
