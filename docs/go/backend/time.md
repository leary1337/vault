# Время и таймеры

Календарные часы могут переводиться. Для измерения длительности нужен устойчивый отсчёт. `time.Time` из `time.Now` может содержать календарное и монотонное время; операции между такими значениями используют монотонную часть. При сериализации она теряется.

Для хранения и передачи обычно выбирают UTC, для отображения — явный часовой пояс. Календарный день в зоне с переходами времени не всегда равен `24*time.Hour`.

## Таймеры: границы версий

`time.After` удобен для одного события. `Timer` даёт управление Stop и Reset. Начиная с Go 1.23, недостижимые незавершённые таймеры и ticker могут собираться GC, а каналы таймеров стали синхронными.

В Go 1.23–1.26 новые правила по умолчанию зависели от `go 1.23` главного модуля; `GODEBUG=asynctimerchan=1` возвращал старые. В Go 1.27 переключатель удалён: правила действуют независимо от строки `go`. После Stop/Reset нового канального Timer старое событие не приходит. `AfterFunc` отличается: он запускает функцию, а не отправляет значение в канал.

## Остановка и ожидание

```go
started := time.Now()
elapsed := time.Since(started) // локальное измерение monotonic clock
_ = elapsed

for {
	select {
	case <-ticker.C:
		// периодическая работа
	case <-ctx.Done():
		ticker.Stop()
		return
	}
}
```

Фрагмент для существующих `ticker` и `ctx`. `Ticker.Stop` прекращает события, но не закрывает `C`; `range ticker.C` сам не завершится. Нужна отмена горутины. Ticker может пропускать события при медленном получателе: это часы, а не надёжная очередь заданий.

`AfterFunc.Stop` не ждёт уже запущенную функцию. Если ожидание нужно, добавьте синхронизацию. Для таймаута запроса обычно подходит контекст с обязательным вызовом CancelFunc.

## Сравнение и тесты

`Time.Equal` сравнивает момент времени. `==` сравнивает также представление, включая location и монотонные данные. Для ключа карты можно нормализовать `t.UTC().Round(0)`, если это соответствует точности контракта.

В тестах принимайте часы как зависимость или используйте `testing/synctest`: стабильный API с Go 1.25, эксперимент в 1.24. Случайные Sleep делают испытания медленными и нестабильными. См. [контекст](../concurrency/context.md) и [утечки](../concurrency/goroutine-leaks.md).

## Проверь себя

1. Закрывает ли `ticker.Stop` канал `C`?
2. Почему `Time.Equal` может отличаться от `==`?

<details>
<summary>Ответы</summary>

1. Нет: для завершения читающей горутины нужен отдельный сигнал.
2. `==` сравнивает представление, Equal — момент времени по правилам библиотеки.
