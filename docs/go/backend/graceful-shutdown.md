# Корректная остановка HTTP-сервера

Сервер прекращает приём, завершает активные запросы и выходит до срока платформы. `Server.Shutdown(ctx)` закрывает слушатели и свободные соединения, затем ждёт активные. Собственные фоновые задачи и захваченные соединения, например многие WebSocket, остаются ответственностью приложения.

## Координация

Сначала снимите готовность с учётом задержки распространения. Затем вызовите Shutdown с новым ограниченным контекстом, дождитесь работы и закройте зависимости. Общий механизм — в [остановке](../concurrency/graceful-shutdown.md).

```go
serveErr := make(chan error, 1)
go func() { serveErr <- srv.ListenAndServe() }()

// После сигнала остановки; main остаётся жить до окончания Shutdown.
if err := srv.Shutdown(shutdownCtx); err != nil {
	_ = srv.Close() // принудительно закрыть обычные connections
	return err
}
if err := <-serveErr; err != nil && !errors.Is(err, http.ErrServerClosed) {
	return err
}
```

Фрагмент функции, возвращающей `error`; нужны `errors`, `net/http`. `srv` создан заранее, `shutdownCtx` имеет новый срок.

`ListenAndServe` после закрытия слушателя возвращает `http.ErrServerClosed`. Это ожидаемый результат, но не доказательство завершения всех обработчиков. Если сразу вернуть `main`, отдельно запущенный Shutdown может не закончиться. Нужно дождаться его результата.

## Ошибки и границы

Ошибка запуска, например занятый порт, должна обрабатываться сразу, а не после ожидания сигнала. При истечении срока зафиксируйте незавершённую работу. Ни Shutdown, ни Close автоматически не закрывают захваченные соединения. Подписки, работников и WebSocket регистрируйте и завершайте отдельно.
