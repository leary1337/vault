# HTTP-сервер

Сервер читает запрос и вызывает обработчик. Для внешних клиентов нужны отдельные ограничения времени, размера данных и дорогой работы. Простой `http.ListenAndServe` создаёт сервер с нулевыми настройками времени: для публичного сервиса задайте их явно.

```go
server := &http.Server{
	Addr:              ":8080",
	Handler:           routes,
	ReadHeaderTimeout: 5 * time.Second,
	ReadTimeout:       15 * time.Second,
	WriteTimeout:      30 * time.Second,
	IdleTimeout:       90 * time.Second,
	MaxHeaderBytes:    1 << 20,
}
```

Числа — пример. Загрузка файлов, потоковые ответы и сроки прокси требуют собственных решений.

## Границы времени

`ReadHeaderTimeout` ограничивает получение заголовков. `ReadTimeout` включает всё чтение запроса и тела, поэтому может быть слишком грубым для загрузки. `WriteTimeout` ограничивает запись ответа с особенностями протокола. `IdleTimeout` ограничивает ожидание следующего запроса на сохранённом соединении.

Контекст ограничивает работу обработчика только при его участии. Сервер не предоставляет полный контроль допуска: используйте предел активных дорогих операций, а ограничения соединений — также на уровне прокси или ОС. Измеряйте число активных запросов и отказов.

## Размер и время — разные ограничения

Фрагмент `ServeHTTP`; нужны `net/http`, `io`, `errors`:

```go
body := http.MaxBytesReader(w, r.Body, 1<<20)
payload, err := io.ReadAll(body)
if err != nil {
	var tooLarge *http.MaxBytesError
	if errors.As(err, &tooLarge) {
		http.Error(w, "body too large", http.StatusRequestEntityTooLarge)
		return
	}
	http.Error(w, "bad body", http.StatusBadRequest)
	return
}
_ = payload // дальше decoding/validation
```

Тело на 10 ГиБ может прийти быстро: таймаут не защитит размер. Небольшое тело может поступать по байту в секунду: размерный лимит не защитит время. `MaxBytesReader` ограничивает байты, а временные настройки и контекст решают другой вопрос.

`WriteTimeout` не останавливает бесконечное CPU-вычисление. Для потока данных общий короткий срок может быть неверным: определите допустимый простой и управление через `ResponseController`, если нужно. Проверяйте фактический протокол и прокси.

TLS, HTTP/2 и `Server.Protocols` выбирайте с учётом клиентов. Не отключайте протокол как случайное лечение без измерения причины.
