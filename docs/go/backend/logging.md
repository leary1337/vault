# Структурированные логи Go

Структурированный лог сохраняет событие и отдельные поля, чтобы их можно было искать и группировать. `log/slog` принимает сообщение и типизированные атрибуты. Передавайте logger как зависимость; контекст нужен обработчику логов, если он использует данные запроса.

```go
logger.InfoContext(ctx, "request completed",
	"method", r.Method,
	"route", routeTemplate,
	"status", status,
	"duration_ms", duration.Milliseconds(),
)
```

Ошибку обычно записывают один раз там, где известен итог операции. Нижние слои добавляют причины и возвращают её. Иначе один отказ становится несколькими записями и искажает статистику.

## Минимальная программа

```go
package main

import (
	"log/slog"
	"os"
)

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	logger.With("service", "ads").Info("ad created", "ad_id", 42)
}
```

Получится одна JSON-запись с `level=INFO`, `msg=ad created`, `service=ads`, `ad_id=42` и временем. Порядок полей не является бизнес-контрактом.

`InfoContext` сам не добавляет trace ID: это делает настроенный Handler или приложение. Аргументы вычисляются даже при выключенном уровне. Перед дорогой подготовкой проверьте `logger.Enabled` либо используйте `LogValuer`.

## Данные и стоимость

Пароли, токены и сырые тела не логируют. Персональные данные требуют удаления лишних полей, срока хранения и контроля доступа. Множество уникальных значений допускается в логах только по подходящей политике стоимости и приватности; в метриках идентификатор пользователя или сырой путь создаст чрезмерное число рядов, поэтому используйте шаблон маршрута.

Повторяющиеся обычные события можно записывать выборочно. Аудит безопасности требует отдельного договора доставки и целостности. Измеряйте объём и скорость логов.
