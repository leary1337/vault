# Основы Go

В Go у каждого значения есть тип: он определяет, какие операции компилятор разрешит выполнить. Например, число можно складывать, а строку — объединять с другой строкой. Проверка типов происходит до запуска программы. Здесь описана семантика Go 1.27; устройство строк подробно разобрано [отдельно](strings-bytes-runes.md).

## Типы и нулевое значение

Переменная без начального значения не содержит случайный мусор: она получает **нулевое значение** своего типа.

| Тип | Нулевое значение |
|---|---|
| Числа, `bool`, `string` | `0`, `false`, `""` соответственно |
| Указатели, функции, срезы, карты, каналы, интерфейсы | `nil` |
| Массивы и структуры | Нулевые значения каждого элемента или поля |

Такой `sync.Mutex` уже пригоден для работы. Но запись в `nil`-карту вызывает панику; отправка и получение на `nil`-канале блокируются навсегда.

## Объявление и присваивание

```go
var retries int // 0
timeout := 2 * time.Second
value, ok := cache[key] // multi-value assignment
left, right = right, left
```

`:=` объявляет хотя бы одну новую переменную, отличную от `_`, в текущем блоке. Присваивание копирует значение. Для числа это само число; для среза — описание массива, длины и ёмкости. Поэтому два среза после присваивания могут менять один массив. Это копирование значения, а не передача переменной по ссылке.

## `new` и `make`

`new(T)` возвращает указатель на нулевое значение `T`. Начиная с Go 1.26, `new(expr)` может создать переменную, сразу содержащую результат выражения. `make` нужен для подготовки среза, карты или канала: он возвращает сам тип, а не указатель.

```go
p := new(int)             // *int, *p == 0
limit := new(int64(300))  // Go 1.26+: *int64, *limit == 300
s := make([]int, 0, 16)   // готовый slice
m := make(map[string]int) // готовая map
ch := make(chan int, 8)   // buffered channel
```

`&T{}` удобно, когда нужны начальные поля структуры. `new` не обещает размещение в куче. Компилятор выбирает стек вызова или кучу, сохраняя правильный срок жизни объекта; это называется анализом выхода значения за пределы вызова (escape analysis).

## Преобразование и проверка типа

Преобразование числа нужно указать явно:

```go
var n int64 = 42
small := int32(n) // explicit conversion; возможна потеря старших битов
```

`T(x)` преобразует значение по правилам языка. Если число не помещается, старшие биты могут потеряться. Операция `x.(T)` решает другую задачу: проверяет конкретный тип значения, уже хранящегося в интерфейсе. См. [интерфейсы](interfaces.md).

## Сравнение значений

Числа, строки, логические значения, указатели и каналы допускают `==`. Массивы и структуры сравнимы, если сравнимы все их элементы или поля. Срезы, карты и функции можно сравнить только с `nil`.

У интерфейсов есть особенность: синтаксически сравнение разрешено, но одинаковый несравнимый конкретный тип внутри обоих значений вызывает панику:

```go
var a any = []int{1}
var b any = []int{1}

// _ = a == b // panic: comparing uncomparable type []int
```

`comparable` задаёт ограничение для параметров типа. `any` — другое имя `interface{}`; оно само по себе не делает значение сравнимым.

## Константы и `iota`

Константы вычисляются при компиляции. Пока тип не выбран контекстом, они могут представлять числа точнее обычного машинного типа. При присваивании значение должно помещаться в выбранный тип.

```go
const untyped = 1 << 40
const typed int64 = 1 << 40

type State uint8

const (
	StateUnknown State = iota
	StateReady
	StateClosed
)
```

`iota` нумерует объявления внутри группы `const` с нуля. Если числа входят во внешний протокол, задавайте их явно: вставка новой строки не должна менять коды уже существующих сообщений.

## Что гарантирует язык

Аргументы и результаты передаются по значению. `int`, `uint` и `uintptr` имеют размер 32 или 64 бита в зависимости от реализации. Строка — неизменяемая последовательность байтов, которая не обязана быть корректным UTF-8. Внутреннее расположение данных среза, карты или интерфейса не является публичным контрактом. Порядок вычисления не определён для всех подвыражений: не связывайте корректность с неоговорённым порядком.

## Область видимости и незаметное затенение

```go
n := 1
if true {
	n := 2         // новая переменная во внутреннем блоке
	fmt.Println(n) // 2
}
fmt.Println(n) // 1
```

Вывод `2`, затем `1` объясняется двумя разными переменными: внутренняя `n` скрывает внешнюю, но не меняет её. Так же можно незаметно скрыть `err` внутри `if`. `go vet ./...` находит часть подозрительных конструкций, но не проверяет бизнес-логику.

Не путайте копию описания общих данных с полным копированием этих данных. Измеряйте производительность своей программы: выбор Go сам по себе не гарантирует ускорения.
