# Гонки данных

Гонка данных возникает при конкурентных обращениях к одному месту памяти без согласованного порядка, если хотя бы одно обращение записывает и они не атомарны. То, что тест обычно проходит, не делает такой доступ корректным.

```go
var n int
go func() { n++ }()
fmt.Println(n) // race, даже если «обычно успевает»
```

Исправление задаёт единственного владельца или синхронизацию: мьютекс, передачу через канал, атомарную операцию либо неизменяемую копию. `Sleep` лишь задерживает выполнение и не создаёт гарантированного порядка.

## Детектор гонок

```bash
go test -race ./...
go test -race -run TestName -count=20 ./path/to/pkg
```

Детектор динамический: он наблюдает реально выполненные пути. Проверяйте конкурентные сценарии и подходящие интеграционные испытания, учитывая дополнительные расходы `-race`. Успешный запуск не доказывает отсутствие всех гонок.

Частые причины — общая карта с писателем, изменяемая переменная замыкания, копии среза с общим массивом и повторное использование переданного буфера. Атомарность части полей не защищает обычные обращения к остальным.

## Счётчик и логическая гонка

Фрагмент внутри `main` для Go 1.25+; нужны `sync`, `sync/atomic`, `fmt`:

```go
var n atomic.Int64
var wg sync.WaitGroup
wg.Go(func() { n.Add(1) })
wg.Wait()
fmt.Println(n.Load()) // 1
```

`Wait` ждёт завершения работников, а atomic согласует их обращения к числу. Одно ожидание без atomic не защищало бы два одновременных `n++`.

Отсутствие гонки памяти не доказывает правильность бизнес-операции. Две транзакции могут прочитать «объявление свободно» и обе продать его, хотя локальные переменные защищены. Нужны ограничение БД, блокировка или условное обновление версии. Это логическая гонка: отдельные безопасные действия сложились в неверный результат.

## Проверь себя

1. Чем гонка данных отличается от логической гонки?
2. Почему WaitGroup не защищает два одновременных `n++`?

<details>
<summary>Ответы</summary>

1. Первая нарушает порядок доступа к памяти; вторая может быть ошибкой сочетания операций без такого нарушения.
2. Она ждёт завершения, но не упорядочивает изменения работников между собой.
