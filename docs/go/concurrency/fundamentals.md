# Основы конкурентности в Go

**Конкурентность** — организация нескольких задач, которые могут продвигаться независимо. **Параллелизм** — их одновременное физическое выполнение. Один повар может чередовать два блюда; два повара могут готовить одновременно. Конкурентная программа Go может работать на одном P, но для параллельного Go-кода нужны доступные ресурсы исполнения.

## Запуск — только начало

`go f()` запускает горутину, не ждёт её и не возвращает результат или ошибку. Планировщик распределяет горутины по потокам ОС. При возврате из `main` процесс завершается, даже если работа ещё идёт.

У горутины должен быть владелец: кто запускает, ограничивает число задач, передаёт отмену, получает ошибку и ждёт завершения. Нужна также понятная реакция на панику. Бесконтрольный запуск превращает всплеск запросов в растущую память и очередь.

## Общие данные

Если горутины читают и меняют одно место памяти без нужного порядка, возникает гонка данных. Выбирайте защиту по условию, которое должно сохраняться целиком. Одно число можно менять атомарно. Перевод между двумя балансами требует общей блокировки или другого целостного обновления. Канал удобен для передачи задания и права изменения данных, а неизменяемый снимок уменьшает число общих изменений.

Канал не автоматически быстрее мьютекса. Закрывает его тот, кто знает, что отправок больше не будет. Закрытие сообщает об окончании потока, но не отменяет произвольные горутины.

## Отмена и ожидание

```go
func worker(ctx context.Context, jobs <-chan Job) error {
	for {
		select {
		case <-ctx.Done():
			return context.Cause(ctx)
		case job, ok := <-jobs:
			if !ok {
				return nil
			}
			if err := process(ctx, job); err != nil {
				return err
			}
		}
	}
}
```

Контекст передаёт сигнал вниз по вызовам; дочерний срок не продлевает родительский. Код и операции ввода-вывода должны замечать отмену. На каналах отменяемыми делают и получение, и отправку. Ошибка возвращается владельцу или собирается группой задач.

Ожидающая сеть, канал или блокировка горутина обычно не расходует CPU, но удерживает память. Пустой цикл с `select { default: }`, напротив, постоянно исполняется и занимает CPU.

## Проверка

Тесты проверяют изменения состояния и завершение. `go test -race` ищет гонки на выполненных путях, но не доказывает их полного отсутствия. Профили блокировок и горутин, а также трасса выполнения помогают различать ожидание, конкуренцию и утечки. Нагрузочный сценарий должен также корректно завершаться.
