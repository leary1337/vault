# Атомарные операции

Атомарная операция неделимо читает или меняет значение: другой участник не увидит его «наполовину». Это подходит для счётчика или публикации готового снимка, но не делает несколько отдельных действий одной транзакцией.

`sync/atomic` задаёт синхронизацию; атомарные операции Go ведут себя как единый последовательный порядок. Предпочитайте типы `atomic.Bool`, `Int64`, `Pointer[T]` и другие типизированные обёртки.

```go
type Metrics struct {
	requests atomic.Uint64
}

func (m *Metrics) Inc()         { m.requests.Add(1) }
func (m *Metrics) Load() uint64 { return m.requests.Load() }
```

## Условное атомарное обновление

CAS сравнивает текущее значение с ожидаемым и меняет только при совпадении. Если кто-то успел изменить его, нужно прочитать свежее и пересчитать результат:

```go
for {
	old := state.Load()
	if state.CompareAndSwap(old, old|flagReady) {
		break
	}
}
```

В повторяемом вычислении нельзя отправлять письмо или делать иной побочный эффект: неудачный CAS приведёт к повтору этого действия. Под высокой конкуренцией цикл может много раз проигрывать; отсутствие блокировки не гарантирует фиксированного времени завершения.

## Публикация снимка

`atomic.Pointer[T]` позволяет сначала полностью создать объект, затем заменить общий указатель через `Store`. Наблюдающий новый указатель читатель получает опубликованное состояние. Но дальнейшие изменения полей требуют отдельной синхронизации. Проще делать опубликованный объект неизменяемым.

## Почему два счётчика не защищают перевод

При `A=100`, `B=0` операции `A.Add(-10)` и `B.Add(10)` атомарны по отдельности. Между ними читатель может увидеть сумму 90. Если сумма всегда должна быть 100, перевод и чтение пары защищайте одним мьютексом либо публикацией одного целого снимка.

ABA — ситуация, когда значение стало A→B→A. Совпавший указатель не доказывает, что логическая версия осталась прежней. Такой алгоритм требует отдельного решения версий и срока жизни.

## Ограничения

Не смешивайте обычные и атомарные обращения к одному значению. Не копируйте атомарные типы после использования; типизированные обёртки помогают соблюдать выравнивание. Несколько горячих счётчиков в одной линии кеша могут мешать друг другу, хотя меняют разные данные: это false sharing. Настройку расположения делайте по измерению для конкретной платформы.
