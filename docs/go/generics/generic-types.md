# Обобщённые типы, aliases и методы

Параметризованный тип сохраняет одну реализацию контейнера для разных типов элементов. **Псевдоним** (alias) — другое имя того же типа; объявление нового определённого типа создаёт отдельный тип.

## Обобщённый тип

```go
type Set[T comparable] map[T]struct{}

func (s Set[T]) Add(value T) {
	s[value] = struct{}{}
}
```

Метод `Add` использует `T` самого `Set`. Параметры получателя записываются в объявлении метода; эта возможность есть с Go 1.18.

## Параметризованные псевдонимы

С Go 1.24 псевдоним может иметь параметры типа:

```go
type StringSet = Set[string]
type Lookup[K comparable, V any] = map[K]V
```

Псевдоним и его целевой тип идентичны. При использовании нужно подставить параметры. Это удобно для совместимости и постепенного изменения API, но не создаёт новую предметную сущность.

## Параметризованные методы

Go 1.27 разрешает собственные параметры типа у метода:

```go
type Stream[T any] []T

func (s Stream[T]) Map[R any](fn func(T) R) Stream[R] {
	out := make(Stream[R], len(s))
	for i, value := range s {
		out[i] = fn(value)
	}
	return out
}
```

Здесь `R` принадлежит `Map`, а не типу получателя. До Go 1.27 такую операцию оформляли отдельной обобщённой функцией.

Метод в интерфейсе по-прежнему не может объявлять собственные параметры типа. Обобщённый метод также не реализует обычный метод интерфейса «для всех подстановок». Если нужен вызов через интерфейс, определяйте конкретные сигнатуры.

## Создание и результат

После объявлений выше внутри `main`; нужны `fmt`, `strconv` и версия языка Go 1.27 для `Map`:

```go
s := make(Set[string])
s.Add("go")
s.Add("go")
fmt.Println(len(s)) // 1

out := Stream[int]{1, 2}.Map(func(n int) string { return strconv.Itoa(n) })
fmt.Println(out) // [1 2], тип Stream[string]
```

Нулевой `Set[T]` содержит `nil`-карту: вызов `Add` паникует. Если нулевой контейнер должен работать, API должен уметь создать и заменить карту у владельца.

Для модуля с `go 1.26` собственный параметр `R` у метода непереносим. Совместимый вариант — функция `Map[T,R](s Stream[T], fn func(T)R)`.

Обобщения уменьшают повторение и сохраняют тип результата. Но сложное ограничение ухудшает понимание API; конкретная стратегия генерации кода не гарантирована. Если абстракция используется один раз и не выражает устойчивую операцию, конкретная функция может быть яснее.

## Проверь себя

1. Почему нулевой `Set` нельзя сразу заполнить через `Add`?
2. Чем параметры `Add` и `Map` отличаются в примере?

<details>
<summary>Ответы</summary>

1. Его карта равна `nil`; нужна инициализация.
2. `Add` использует параметр типа получателя, `Map` объявляет свой параметр метода — возможность Go 1.27.
