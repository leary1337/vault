# Структуры в Go

Структура объединяет связанные поля в одно значение. При копировании числовые поля становятся независимыми, а указатели, срезы и карты могут продолжать вести к общим данным. Нулевое значение структуры состоит из нулевых значений её полей.

## Объявление и создание

```go
type User struct {
	ID   int64
	Name string
}

u := User{ID: 42, Name: "Ada"}
```

В коде другого пакета указывайте имена полей в литерале: добавление или перестановка полей не изменит смысл. Литерал без имён связывает вызывающий код с порядком полей; `go vet` предупреждает о многих таких случаях.

## Сравнение значений

Структура допускает `==`, если сравнимо каждое поле. Тогда её можно использовать ключом карты. Поле-срез, карта или функция делает всю структуру несравнимой. Если равенство должно игнорировать кеш или служебную дату, явно определите функцию сравнения.

## Методы и получатели-указатели

Получатель-значение получает копию структуры. Получатель-указатель может менять исходный объект и не копировать крупное значение. Выбор также влияет на реализацию интерфейсов. Тип с `sync.Mutex` нельзя копировать после первого использования: новая блокировка уже не защищает общие данные прежней. `go vet` с анализатором `copylocks` помогает находить такие ошибки.

## Встраивание

Встроенное поле позволяет сокращать обращение к его полям и методам. Это не наследование: вложенный объект остаётся отдельным полем. Собственное поле или метод внешней структуры может скрыть продвинутый. Встраивание публичного чужого типа также раскрывает его методы как часть вашего API.

## Метки полей

Метка поля — строка, которую библиотека читает через reflection. Смысл `json`, проверки или сопоставления с БД задаёт конкретная библиотека. Метки участвуют в идентичности типов с оговорками правил присваивания; распространённые синтаксические ошибки проверяет `go vet`.

```go
type Request struct {
	Name string `json:"name"`
}
```

Неэкспортируемые поля обычно недоступны кодировщику другого пакета. Метка не заменяет проверку прав. Для внешнего запроса или ответа определяйте явную структуру данных и переносите разрешённые поля: иначе можно случайно принимать или раскрывать внутреннее состояние.

## Расположение и выравнивание

Компилятор добавляет промежутки между полями для выравнивания. `unsafe.Sizeof`, `Alignof` и `Offsetof` показывают расположение для конкретной сборки. Перестановка полей иногда экономит память на миллионах объектов, но её эффект нужно измерить.

Нельзя передавать сырую память структуры как переносимый формат: промежутки, порядок байтов и указатели различаются. Используйте явное кодирование.

## Пример встраивания

```go
type Address struct{ City string }
type UserWithAddress struct {
	Address
	Name string
}

// внутри main:
u := UserWithAddress{Address: Address{City: "Москва"}, Name: "Анна"}
fmt.Println(u.City) // Москва: сокращённый selector u.Address.City
```

`u.City` сокращает доступ к `u.Address.City`. Это не отношение «User является Address». Если у `User` появится собственный `City`, сокращённое обращение начнёт выбирать его, хотя вложенное поле останется прежним.

## Проверь себя

1. Почему структура со срезом не подходит ключом карты?
2. Что означает `u.City` при встраивании `Address`?

<details>
<summary>Ответы</summary>

1. Срез не сравним, поэтому не сравнима и вся структура.
2. Сокращённое обращение к вложенному полю, а не наследование.
