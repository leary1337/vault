# Модульные тесты

Модульный тест проверяет небольшой контракт без настоящей сети и БД. Он отвечает на вопрос «какое поведение нельзя сломать», а не повторяет последовательность внутренних вызовов. Быстрый тест должен контролировать время, случайность и окружение.

```go
func TestPrice_Discount(t *testing.T) {
	got, err := Price(1_000, 15)
	if err != nil {
		t.Fatalf("Price returned error: %v", err)
	}
	if want := int64(850); got != want {
		t.Fatalf("Price() = %d, want %d", got, want)
	}
}
```

## Результат на примере цены

```go
func Price(amount int64, discount int64) (int64, error) {
	if amount < 0 || discount < 0 || discount > 100 {
		return 0, errors.New("invalid price or discount")
	}
	// Деление до умножения избегает overflow amount*100.
	keep := 100 - discount
	return amount/100*keep + amount%100*keep/100, nil
}
```

Нужен `errors`. Цена — целые минимальные денежные единицы. Скидка округляется вниз: 1000 при 15% даёт 850, 1 при 50% — 0. Проверьте также 0/100%, отрицательный ввод и максимальную сумму. `float64` для денег требует отдельного правила точности.

## Ресурсы и параллельная работа

`t.Helper` переносит место сообщения об ошибке к вызывающему проверку. `t.Cleanup` освобождает ресурсы даже при неудаче; `t.TempDir` создаёт отдельный каталог.

`t.Fatal` завершает только текущую тестовую горутину через Goexit. Работник должен вернуть ошибку владельцу теста, а не вызывать Fatal сам. Дождитесь запущенной работы и согласуйте её остановку. Случайный Sleep не исправляет гонку: используйте синхронизацию, управляемые часы или подходящий `testing/synctest`.
