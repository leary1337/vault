# Детектор гонок в тестах

Флаг `-race` полезен только при реально выполненном конфликтующем сценарии. Тест должен дождаться работников; иначе он может закончиться до ошибочного доступа.

```bash
go test -race ./...
go test -race -run TestConcurrent -count=50 ./pkg
```

Детектор наблюдает выполненные пути. Дополнительный расход CPU и памяти меняет время работы, поэтому выделяйте подходящее задание CI и конкурентные сценарии. Не исправляйте отчёт с помощью Sleep: задайте владение и порядок. Подробности — в [детекторе](../performance/race-detector.md) и [гонках](../concurrency/data-races.md).

## Два работника

```go
func TestConcurrentCount(t *testing.T) {
	var count atomic.Int64
	var wg sync.WaitGroup
	for range 2 {
		wg.Go(func() {
			for range 1000 {
				count.Add(1)
			}
		})
	}
	wg.Wait()
	if got := count.Load(); got != 2000 {
		t.Fatalf("got %d", got)
	}
}
```

Нужны `sync`, `sync/atomic`, `testing`, Go 1.25+. Ожидается 2000: атомарные обращения согласованы, Wait ждёт завершение. Если заменить их на обычный `count++`, Wait не защитит работников друг от друга.

На некоторых платформах нужны cgo и C-компилятор. Невозможность включить режим должна быть отмечена отдельно: обычный тест не является успешным запуском детектора.
