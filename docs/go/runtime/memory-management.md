# Управление памятью Go

**Стек** хранит данные текущих вызовов горутины. **Куча** хранит объекты, срок жизни которых нельзя безопасно ограничить одним вызовом. Компилятор и среда выполнения выбирают размещение так, чтобы значение оставалось доступным столько, сколько нужно.

Здесь описан стандартный Go 1.27. Язык не обещает конкретного размещения каждого значения.

## Стек и куча

Стек горутины может расти и перемещаться. Компилятор анализирует, выходит ли значение за пределы своего вызова (escape analysis). Поэтому вернуть адрес локальной переменной безопасно:

```go
func newCounter() *int {
	n := 0
	return &n // compiler обеспечит lifetime; вероятный escape
}
```

Срок жизни `n` будет продлён при необходимости. `new`, литерал структуры и получатель-указатель сами по себе не определяют место хранения. Для конкретной версии компилятора:

```bash
go build -gcflags="all=-m=2" ./...
go test -bench=. -benchmem ./...
```

Первая команда объясняет решения размещения и встраивания функций. Вторая измеряет время и выделения памяти. Сообщение «перемещено в кучу» ещё не доказывает проблему производительности: попытка убрать выделение может ухудшить код.

## Распределитель памяти

Распределитель памяти группирует небольшие объекты по размеру. Локальные запасы у P позволяют многим горутинам получать память без постоянной общей блокировки. Когда локального запаса не хватает, используются общие области. Большие объекты обрабатываются иначе.

Точные размеры классов и внутренние структуры меняются. Для приложения важны размер объекта, число указателей, срок жизни и скорость выделений: они определяют работу распределителя и сборщика мусора.

## Возврат страниц, RSS и виртуальная память

Освобождённая сборщиком память может остаться у Go для повторного использования. Механизм **scavenger** возвращает подходящие свободные страницы ОС. Поэтому уменьшение живой кучи не обязано сразу уменьшить RSS — объём страниц процесса в RAM.

Профиль кучи не включает весь RSS. В процессе есть также стеки, служебные данные, отображения файлов, память C и `mmap`. Буферы сокетов и файловый кеш имеют свой учёт ОС и cgroup. Большой VSS показывает занятое виртуальное адресное пространство и сам по себе не означает такой же расход физической памяти. Сопоставляйте `runtime/metrics`, профиль кучи и показатели ОС.

## Удержание данных и фрагментация

Память может удерживать выросший кеш, маленький срез большого массива, незавершённая горутина или пул с крупными буферами. При **фрагментации** части областей свободны, но оставшиеся живые объекты не позволяют вернуть целую область ОС.

`debug.FreeOSMemory` запускает сборку и попытку активного возврата памяти. Это диагностический или редкий эксплуатационный инструмент; он не убирает живые ссылки и обычно не нужен на пути каждого запроса.

## `sync.Pool`

Пул хранит временные взаимозаменяемые объекты. Среда выполнения может удалить их в любой момент, поэтому пул не является надёжным хранилищем. При подходящей нагрузке он уменьшает выделения, но сохранение редких больших буферов увеличивает удерживаемую память. Ограничивайте размер возвращаемых объектов.

## Отделить удержание от возврата ОС

Если `inuse_space` растёт при одинаковой нагрузке, ищите сохраняющие ссылки структуры. Если куча стабильна, а RSS растёт, проверяйте стеки, C, отображения и учёт ОС. Если куча уменьшилась, а RSS нет, возможно, свободная память пока осталась у распределителя.

```go
func keptPrefix(data []byte) []byte {
	n := min(len(data), 16)
	return bytes.Clone(data[:n])
}
```

Нужен `bytes`; `min` доступен с Go 1.21. Возвращённый префикс имеет собственные байты и не удерживает большой исходный массив. Цена — небольшое копирование. Оно нужно не каждому срезу: сравните размеры и сроки жизни.

`unsafe.Sizeof(slice)` измеряет само описание среза, а не массив. Размер всех данных карты тоже нельзя получить одним `Sizeof`. Считайте память по структуре владения и измерениям, включая служебные расходы.

## Проверь себя

1. Почему `Sizeof(slice)` не показывает удержанную память?
2. Почему возврат адреса локальной переменной безопасен?

<details>
<summary>Ответы</summary>

1. Он измеряет описание среза; массив находится отдельно.
2. Go обеспечивает срок жизни значения, при необходимости размещая его в куче.
