# Ожидание сети: netpoller

Представьте тысячу соединений, которые большую часть времени ждут данные. Если каждому выделить ожидающий поток ОС, потоки будут расходоваться без полезной работы. Go обычно приостанавливает только горутину, а ожидание событий сети передаёт механизму ОС — **netpoller**.

Это описание стандартной среды выполнения Go 1.27. На Linux используются неблокирующие сокеты и epoll; на BSD/macOS — kqueue; на Windows — асинхронные операции и IOCP. Последний сообщает о завершении, поэтому объяснять все платформы только «готовностью сокета» неверно.

## Как продолжается операция

На Linux чтение, которому пока не хватает данных, позволяет горутине приостановиться. Событие ОС или истечение срока ожидания делает её готовой к выполнению. Затем планировщик должен снова выделить время. Событие готовности не означает, что пришло всё сообщение приложения.

Тысяча ожидающих соединений не требует тысячи одновременно работающих потоков, но каждое соединение всё равно занимает файловый дескриптор, буферы ядра и память приложения.

## Что не покрывает модель

Обычные файлы часто не поддерживают такую же модель сетевой готовности, и работа с ними может блокировать поток. DNS зависит от платформы и выбранного механизма разрешения имён; вариант через cgo (вызов C-кода из Go) может использовать потоки. Произвольный вызов C тоже не превращается в операцию netpoller.

TCP передаёт поток байтов. Правило выделения сообщений — длина, разделитель или иной формат — задаёт приложение, а не ожидание событий ОС.

## Deadlines

Предельный срок сетевой операции — абсолютное время. Он применяется и к текущим, и к будущим операциям на соединении. Контекст сам по себе не отменяет произвольный `net.Conn.Read`: API должен связать отмену с изменением срока или закрытием соединения.

## Deadline действует на будущие операции тоже

Фрагмент функции, возвращающей `error`, для уже открытого `net.Conn`; нужны `time` и `io`:

```go
if err := conn.SetReadDeadline(time.Now().Add(time.Second)); err != nil {
	return err
}
buf := make([]byte, 4)
_, err := io.ReadFull(conn, buf)
if err != nil {
	return err
}
if err := conn.SetReadDeadline(time.Time{}); err != nil {
	return err
}
```

`ReadFull` получит ровно четыре байта либо ошибку; один обычный `Read` может дать только часть. Нулевое время снимает ранее заданный срок. Если оставить истёкший срок и снова использовать соединение, следующее чтение сразу завершится таймаутом.

Несколько независимых горутин не должны бесконтрольно менять сроки одного соединения: назначьте владельца или общий протокол управления.
