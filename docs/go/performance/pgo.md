# Оптимизация по профилю: PGO

PGO даёт компилятору профиль CPU вашей программы. Он показывает, какие вызовы действительно частые, и помогает выбрать встраивание и прямые вызовы вместо некоторых интерфейсных. Семантика программы от этого не меняется.

## Как применять

Соберите профиль стабильной версии под типичной нагрузкой. Сохраните как `default.pgo` в пакете main или передайте `go build -pgo=profile.pprof`. Проверьте новую сборку обычными тестами и нагрузкой.

```bash
go build -pgo=off -o service-baseline ./cmd/service
go build -pgo=cpu.pprof -o service-pgo ./cmd/service
```

`cpu.pprof` собран заранее. Контрольную сборку без PGO сравнивайте на тех же данных: CPU на запрос, задержка, ошибки и память. Профиль редкой тяжёлой операции не представляет API, где 95% запросов короткие.

## Происхождение и обновление

Профиль — вход сборки. Сохраняйте дату, версию кода и Go, состав нагрузки, оборудование и способ получения. Удаляйте чувствительные метки и пути. После изменения потока запросов или значительного изменения структуры кода он может стать неподходящим.

Не требуется совпадение каждой строки с новой программой, но эффект измеряется заново. Отсутствие выигрыша — нормальный результат эксперимента. PGO не заменяет исправление алгоритма и не означает автоматическую необходимость собирать профиль на каждом запросе.
