# Анализ выхода значения за пределы вызова

Компилятор должен сохранить значение доступным весь нужный срок. Если оно не может безопасно жить в стеке одного вызова, память может быть размещена в куче. Это решение называется **escape analysis**.

```bash
go build -gcflags="all=-m=2" ./...
```

`escapes to heap` объясняет размещение в куче, `leaking param` — передачу указателя или вложенной ссылки дальше. Последнее не означает обязательное новое выделение на каждый вызов. Диагностика зависит от версии, встраивания функций и контекста.

## Один синтаксис — разные решения

```go
func pointer() *int { n := 42; return &n }
func value() int    { n := 42; return n }
```

Возвращённый указатель может пережить исходный вызов. Но после встраивания компилятор иногда доказывает короткий срок на месте использования и оставляет память в стеке. Для первого сравнения `go build -gcflags='-m=2 -l'` отключает встраивание выбранного пакета; затем проверьте обычную оптимизированную сборку.

Получатель-указатель, замыкание или интерфейс сами по себе не гарантируют кучевого выделения. Влияют срок, сохранение в другом объекте, неизвестный вызов, динамический или слишком большой размер.

## Когда исправлять

Сначала профиль выделений, затем часто работающий участок и benchmark с `-benchmem`. После изменения представления или срока сравните результат. Увеличение копирования и сложности ради редкого дешёвого объекта может ухудшить программу. Сообщение компилятора — объяснение, а не отдельная цель «убрать всё».
