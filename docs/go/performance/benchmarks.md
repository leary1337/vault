# Измерения производительности

Benchmark многократно выполняет операцию и оценивает её стоимость. Для сравнения гипотез нужны одинаковые входы и условия. В Go 1.24+ новый тест обычно использует `b.Loop`:

```go
func BenchmarkEncode(b *testing.B) {
	input := makeFixture()
	for b.Loop() {
		encode(input)
	}
}
```

Подготовка до первого Loop и завершение после него не входят в измеряемый интервал. Не смешивайте Loop и цикл по `b.N`. В Go 1.27.1 компилятор сохраняет нужные аргументы, результаты и присвоенные переменные внутри синтаксического `for b.Loop() { ... }`, чтобы не удалить измеряемую работу. Это не отключает все оптимизации и не обещает сохранить произвольную работу внутри помощника.

```bash
go test -run='^$' -bench=BenchmarkEncode -benchmem -count=10 ./pkg > before.txt
go test -run='^$' -bench=BenchmarkEncode -benchmem -count=10 ./pkg > after.txt
benchstat before.txt after.txt
```

## Самодостаточная операция

В `encode_test.go` пакета `encode`; нужны `strconv`, `testing`:

```go
func BenchmarkFormatID(b *testing.B) {
	for b.Loop() {
		_ = strconv.FormatInt(123456789, 10)
	}
}
```

`go test -run='^$' -bench=FormatID -benchmem -count=5` выдаёт `ns/op`, `B/op`, `allocs/op`: время, выделенные байты и число выделений на операцию. Фиксированных чисел нет: они зависят от версии и оборудования. Разница в несколько наносекунд одного запуска может быть шумом. Сравнивайте выборки через benchstat.

## Качество результата

Фиксируйте Go, ОС, архитектуру, режим CPU и входные данные; уменьшайте постороннюю нагрузку. Корректность проверяйте вне измеряемого цикла. `RunParallel` подходит одновременной работе, но `ns/op` отражает суммарную пропускную способность, а не p99 одного запроса.

Микроизмерение не показывает очереди, сеть и реальную конкуренцию сервиса. Пользу изменения подтверждайте профилем и соответствующей нагрузочной проверкой.
