# Платформенная секция

Платформенная секция проверяет, понимаете ли вы поведение языка и сервиса: что происходит с памятью, параллельной работой, сетью и ошибками. Важно связать строку кода с наблюдаемым последствием, а не только назвать правило.

По присланному [документу для кандидатов](https://docs.google.com/document/d/1sHCn1giSMQmMoBlmOyfF8mcPo2yXZmJveGhmjVeTyd4/edit), прочитанному 26 октября 2026, секция длится **1 час**, для Go указаны **2–3 задачи**. Нужно написать свой код либо прочитать и прокомментировать чужой. Проверяют основной язык и его экосистему. В документе есть направления для разных языков; кандидату Go не нужно готовить их все. По сообщению рекрутера встреча проходит с камерой, в отдельный день.

## Как разбирать фрагмент

Сначала скажите, что код должен сделать при успехе. Затем пройдите отказ: запрос отменён, сеть отвечает медленно, вход слишком большой, два вызова меняют общий объект. Кто закрывает ресурс? Кто сообщает ошибку? Может ли оставшаяся горутина закончить? Ответ должен описывать конкретную цепочку.

Проверьте через `httptest`: задержанный ответ прерывается по сроку, HTTP 500 не считается успешным бизнес-ответом, слишком большое тело отклоняется. В работающем сервисе сопоставьте число соединений, ожидание пула и задержку внешнего сервиса. Рост одной метрики памяти ещё не доказывает утечку.

## Пример чтения кода: забытый ответ HTTP

```go
resp, err := client.Get(url)
if err != nil {
    return err
}
return json.NewDecoder(resp.Body).Decode(&result)
```

Это фрагмент с уже существующими `client`, `url`, `result`. После получения ответа код не закрывает `resp.Body`: занятый сетевой ресурс может не вернуться в пул. Запрос не связан с контекстом вызывающего, поэтому отмена не передаётся автоматически. Ответ HTTP 500 сам по себе не даёт ошибку `client.Get`. Исправьте создание через `NewRequestWithContext`, проверку статуса, закрытие тела через `defer` и предел читаемого размера. Для повторного использования HTTP/1 обычно нужно дочитать тело до конца и закрыть, но бесконечно вычитывать огромный ошибочный ответ нельзя.

Дополнительная проверка: ответ слишком большого размера должен быть отклонён до неограниченного выделения памяти. Для повторного использования соединений отдельно проверяйте закрытие тела на всех ветках, включая ошибку декодирования.

Спецификация не гарантирует порядок обхода map. `GOMAXPROCS` ограничивает одновременное исполнение Go-кода, не общее число потоков ОС. На уточнение «всегда ли?» назовите условие гарантии и способ проверки конкретной реализации.
