# Репетиция интервью

Репетиция показывает, где объяснение ломается при уточнении. Партнёр или голосовой помощник задаёт вопрос, вы отвечаете без подсказки, затем вместе разбираете конкретную ошибку. Это проверка переносимого навыка, не реконструкция закрытых вопросов Avito.

## Выбрать один навык

Для основ возьмите один механизм, например видимость строк или повтор HTTP. Для программирования решите одну задачу, объяснив границы и сложность. Для платформенной секции разберите фрагмент с отменой, общим состоянием или незакрытым ресурсом. Для проектирования пройдите один пользовательский путь и два отказа. Для опыта расскажите один случай с личным вкладом.

Можно ограничить разговор 20–60 минутами по доступному времени. Эти числа относятся к вашей репетиции, не к расписанию интервью компании. Важно оставить время на разбор, а не пройти максимум тем.

## Как давать обратную связь

Сначала кандидат формулирует, в чём сомневается. Затем собеседник записывает наблюдение: точное неверное утверждение, пропущенный шаг или контрпример. «Сохранил offset до эффекта и поэтому допускает потерю» полезнее «плохо знает Kafka».

Попросите исправленное объяснение и новый пример. Для кода запустите компиляцию и тесты, включая границы и отмену, если она предусмотрена. Для схемы проверьте, описан ли результат каждого отказа. Одна удачная репетиция не подтверждает уровень автоматически, но даёт конкретную следующую проверку.

## Готовый пример короткой репетиции

Вопрос: «Получатель Kafka записал платёж в БД и упал до сохранения позиции. Что случится?» Запись повторится; inbox и бизнес-изменение должны сохраняться вместе, позиция — после них. Уточнения: что если маркер удалён слишком рано, идентификатор меняется при повторе или списание выполняет внешний HTTP API? Проверяется граница атомарности, не знание слова exactly-once.

Вопрос: «Два врача увидели двух дежурных и каждый снял себя». Нарисуйте две транзакции и объясните нарушение общего правила разными строками — write skew. Serializable требует повтора всей транзакции; общая блокируемая строка может защитить правило другим способом. Блокировка только собственной строки не обязательно поможет.

Запишите точную ошибку: «сказал, что Repeatable Read исключает все аномалии», а не «плохо знаю БД». Попросите контрпример и исправленную формулировку. Для кода после объяснения запустите тесты пустого входа, дублей и предусмотренной отмены. Результат репетиции — наблюдения о навыке, не гарантированный уровень или оффер.
